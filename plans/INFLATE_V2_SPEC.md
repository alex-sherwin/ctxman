# Context Inflate v2: inflate into a working directory (implementation spec, 2026-10-17)

Binding for the coding packets V1-V4 (§16). Read `AGENTS.md`, `plans/INFLATE_V2_BRIEF.md` (user requirements) and
this file; `plans/INFLATE_SPEC.md` describes v1 (history; the code wins). Round 2 (`plans/ROUND2_BACKEND_SPEC.md`,
`plans/ROUND2_UI_SPEC.md`) lands FIRST: this spec is written against its names (kit `Select` v2, `OrderedList`, kit
`Table`, `src/datasets/arktypes.ts`, `schemas/*.schema.json`, `withSchemaComment`, `src/lib/ide.ts`,
`POST /api/ide/open`). Unknowns are decided here; do not invent alternatives. Markdown examples use `~~~~` outer
fences. `<D>` = data dir (`resolveDataDir()`), `<R>` = repo root (`process.cwd()`), `<H>` = `os.homedir()`,
`<W>` = the absolute working directory being inflated.

## 0. Summary, decisions, deviations

Inflate v2 adds a second output: a **working directory** `<W>` that an AI coding harness is started in. A run places
material in `<W>` (symlinks to okf bundles, copied skills, cloned / symlinked repos, installed remote skills), writes
`<W>/LLM_CONTEXT.md` (the v1 document with every path RELATIVE to `<W>` plus a directory map), optional
`CLAUDE.md` / `AGENTS.md` / `.gitignore` stubs, and `<W>/.ctxman-inflate.json` (what ctxman owns there). The v1
single-document render (`/api/inflate/render`, `/api/inflate/write`, Copy / Download) is unchanged and stays the
"no directory" case with absolute paths.

Two axes per item: **mode** (v1, how the item is REPRESENTED in the document) and **material** (new, what is PLACED
in `<W>`). Material only matters when a directory is set.

| # | decision | why |
|---|---|---|
| D1 | Run-time overrides are applied BEFORE expansion: PURE `applyRunOverrides(recipe, run) → RecipeData`; the planner, renderer and checks only ever see one effective recipe. "Save overrides to recipe" = the same function applied to the working copy. | one code path; no override layer inside expand/plan/render |
| D2 | `planMaterialization` is PURE (`src/lib/inflate/material-plan.ts`) and takes the expanded plan + gathered paths + the previous manifest; the NODE executor (`material-exec.ts`) re-checks every precondition at run time. | dry run = exact step list; executor never trusts the plan blindly |
| D3 | `material-exec.ts` is NODE; process spawning is injected (`ProcRunner`, implemented by new SERVER `src/lib/proc.ts` `spawnCapture`). `run-script.ts` is NOT reused (node-script specific: execPath, data-dir env, 1 MiB capture, no line callback). | unit tests drive the executor with real git and temp dirs, or a fake runner |
| D4 | Archives: spawn `tar` (`-xzf` for .tar.gz/.tgz, `-xf` for .zip), fallback `unzip -q -o` for .zip when tar fails; no npm dependency. Extract to a stage dir, then locate the skill folder in Node (subpath, else SKILL.md at the root, else a single wrapper dir containing SKILL.md). `--strip-components` is NOT used. | §1: bsdtar (macOS, Windows 10+) extracts zip; GNU tar does not; archive wrapper layout is unknown in advance |
| D5 | Downloads use Node 24 `fetch` streamed to a file (`Readable.fromWeb` + `pipeline`), cap 256 MiB, 10 min timeout. No curl. | §1 verified |
| D6 | Progress = in-memory job store + polling `GET /api/inflate/jobs/:id` every 500 ms. No SSE. | dev full reloads and HMR would cut streams; polling needs no reconnect logic; a job document is small (≤ ~100 steps × ≤20 tail lines); local server, negligible cost; the Astro node adapter needs nothing special |
| D7 | One running job at a time (409 `busy`); store keeps the last 20 finished jobs; singleton on `globalThis` (survives Vite module re-instantiation; lost on server restart, the UI says so). | brief |
| D8 | Ownership: ctxman deletes or replaces ONLY paths recorded in the previous `.ctxman-inflate.json` (plus "adopt" of an identical symlink / matching git clone). Clones with local changes, edited stubs and paths whose type changed are kept with a warning. | brief safety rule |
| D9 | The working dir must be outside the ctxman repo and the data dir (and must not contain them), not `/`, not `<H>`, no `node_modules`/`.git` segment; a non-empty dir needs a ctxman manifest or `allowNonEmpty`. | brief + Vite watches `<R>` (a clone under `<R>` would flood the watcher) |
| D10 | e2e git fixture: a local repo under `.tmp/e2e-git/` reached through git's own `url.<file-url>.insteadOf=<https uri>` via `GIT_CONFIG_COUNT` env on the e2e web server; the reference `uri` stays a valid https git URI. `remote-uri.ts` is NOT widened to `file://` / plain paths. | §1: `git clone /abs` ignores `--depth`; `file:///…` is rejected by `isGitUri` and its tests on purpose |
| D11 | `LLM_CONTEXT.md` is always regenerated by a run (a recorded context file is overwritten, with a warning when it was edited); stubs (`CLAUDE.md`, `AGENTS.md`, `.gitignore`) are only written when absent or recorded with an unchanged sha256. | the context file is output; stubs are user-editable |
| D12 | The Claude Code stub imports the document with a bare `@LLM_CONTEXT.md` line (Claude Code loads it at session start); the AGENTS.md stub says "read it first". | harness auto-loads its instructions file |
| D13 | Preview of a recipe with a directory shows the RELATIVE document (from the dry run) by default; a `paths=absolute` URL toggle shows the v1 render and the v1 "Write to path" box. | brief: preview shows what will be written; v1 write keeps working |
| D14 | Remote skills install into `<skillsDir>/<basename(subpath)>` when the subpath's last segment is a valid entry name, else `<skillsDir>/<reference slug>`. | agentskills.io: the folder name must equal the skill `name` (e.g. `anthropic-skills` → `skill-creator`) |
| D15 | No `symlinkAs` option: directory links are `'junction'` on win32 and `'dir'` elsewhere, always absolute targets. | junctions need no admin / Developer Mode and must be absolute (Node docs); nothing to choose on POSIX |
| D16 | Test-only hook `CTXMAN_INFLATE_STEP_DELAY_MS` (int 0..5000, read by `jobs.ts` per run) sleeps before each step; set only by the e2e web server (300). | deterministic cancel test without network |

Deviations from the brief / orchestrator task: D1 (planner signature takes the effective plan, not `(plan, recipe,
overrides)`); D4 (no `--strip-components`; extract step has no `strip` field); D10 (no plain-path `remote-repo` uri);
D14; D15; "Skills installed" section is titled `## Skills` (it also lists skills that are only mentioned); seed gets
`output.primary: reference/astro-docs` (the task said both "no primary" and "astro-docs → clone, primary"; the
worked example needs the primary, so it is set); `POST /api/ide/open` gets a `{ dir }` body variant (not `{ path }`:
ROUND2 already uses `path` for a bundle-relative file).

Dependencies added: **none** (git, tar, unzip are system tools; fetch, crypto, fs.cp are Node built-ins).

Windows (from Node docs; no Windows host here, so marked unverified): `fs.symlink(target, path, 'junction')` makes a
junction (no admin; target normalized to absolute; local volumes only); `'dir'` symlinks need admin or Developer
Mode (EPERM otherwise). libuv's `unlink` removes directory symlinks and junctions; fall back to `fs.rmdir(link)`
(non-recursive) on `EPERM`/`EISDIR`. Windows 10 1803+ ships `C:\Windows\System32\tar.exe` (bsdtar: tgz and zip);
`spawn('git')` with `shell: false` resolves `git.exe` through PATH. Linux GNU tar auto-detects gzip with `-xzf` but
cannot read zip (→ `unzip` fallback).

### 6.2 Algorithm (deterministic)

1. `o` = effective `recipe.output` (contextFile default). Items = included item segments with a kind, in segment
   order. For each, `material` from the segment; build its `MaterialView` (`dest = material === 'none' ? null :
   materialDest(…)`, `sourceAbs` = `content.items[key].rootAbs` for okf/skill, `content.items[key].local.root`
   for local-repo; `uri`/`subpath`/`owner` from `meta.ref`; `depth`/`branch`/`sparse` from `materialOptions`
   (`sparse = subpathOnly === true && cleanSubpath(ref.subpath) !== ''`; branch `''` → null).
2. Demote to `none` with a warning (view keeps `material: 'none'`, no step):
   - `dest` already taken by an earlier item → `dest-collision` `${key}: ${dest} is already used by ${other}; nothing placed`.
   - local-repo symlink and `local.exists === false` → `source-missing` `${key}: ${local.root} does not exist; nothing placed`.
   - remote-repo clone / remote-skill git install without git (`!tools.git`) → `tool-missing` `${key}: git is not installed; nothing placed`.
   - remote-skill archive install without tar and (zip: without tar AND unzip) → `tool-missing` `${key}: tar is not installed; nothing placed`.
   - remote-skill whose `meta.uriKind` is undefined → `source-missing` `${key}: unknown URI kind; nothing placed`.
3. `primary` = `plan.primary.key` when `plan.primary.status === 'ok'` and its view still has a dest, else null
   (`primary-invalid` warning already in plan.warnings; add one only for the demotion case:
   `primary ${key} is not placed in the directory`).
4. Owned paths `P` = dests of step-bearing views ∪ `contextFile` ∪ stub files that will be written (stubs: resolved
   `o.stubs[id] ?? stubDefaults(target)[id]`; `gitignore` only when some view has a dest; a stub whose file name
   equals `contextFile` case-insensitively is not written).
5. Steps in this order (each group in segment order):
   1. `ensureDir` (expect `keep` when `dirExists`, else `create`; `fatal`).
   2. `remove` for every `previous.entries[]` whose `path ∉ P` and that is not under a path in `P` (path asc).
   3. okf `symlink` / `copyDir`; 4. skill `copyDir`; 5. local-repo `symlink`; 6. remote-repo `gitClone` /
      `gitUpdate` (`gitUpdate` iff previous has a `clone` entry at the same path with the same `uri`);
   7. remote-skill: git → `gitClone{ stage: true, path: '.ctxman-tmp/<slug>', depth: 1, sparse: subpath, branch }`
      then `placeSkill{ stage: '.ctxman-tmp/<slug>', after: [clone id] }`; archive → `download{ path:
      '.ctxman-tmp/<slug>.<tgz|zip>' }`, `extract{ path: '.ctxman-tmp/<slug>', archive, after: [dl] }`,
      `placeSkill{ after: [x] }`. `format` = `zip` when the URL pathname ends `.zip` (case-insensitive), else `tgz`.
   8. `cleanupStage` (`always`; only when group 7 has steps).
   9. `writeContext` (path = contextFile). 10. `writeFile` stubs: `claude-md`, `agents-md`, `gitignore` (content §6.5).
   11. `writeManifest` (`always`).
   `expect` for 3-5 and `placeSkill`: `replace` when `previous` has an entry at the path, else `create`; gitClone
   `create`; gitUpdate `update`; remove `remove`; write* `write`.
6. Warning `manifest-other-recipe` when `previous.recipe !== recipe.name`:
   `this directory was inflated from recipe "${previous.recipe}"; ${n} of its paths will be removed`.

### 7.1 Output dir checks


In order, first failure wins (messages exact): 1. not a string / blank → `dir is required`; length > 1024 or NUL →
`dir is not valid`. 2. `~` → `<H>`; `~/x` / `~\x` → `path.join(<H>, x)`; `~user…` → `dir must be absolute or start
with ~/`. 3. `!path.isAbsolute` → `dir must be absolute or start with ~/`. 4. `abs = path.resolve(p)`;
`path.parse(abs).root === abs` → `dir must not be a filesystem root`; `abs === path.resolve(<H>)` → `dir must not
be your home directory`. 5. any segment (lower-cased) `node_modules` / `.git` → `dir must not be inside
node_modules or .git`. 6. `abs` inside-or-equal `<D>` or `<D>` inside `abs` → `dir must not contain or be inside the
data directory`. 7. same for `<R>` → `dir must not contain or be inside the ctxman repository`.
"inside" = `rel = path.relative(base, abs)`; `rel === '' || (!rel.startsWith('..') && !path.isAbsolute(rel))`.

### 7.4 Cleanup rule (summary for docs)

A path is removed only when (a) the previous manifest lists it, (b) the new plan does not own it, (c) it still is
what ctxman created (type check), and (d) clones are clean (no porcelain lines, not ahead) and files are unedited
(sha256). Anything else is kept and reported. Nothing outside recorded paths is ever touched; symlinks are
unlinked, never followed.

### 7.5 Re-run behaviour (what the e2e asserts)

Second identical run: okf/local symlinks `unchanged`, copies `replaced`, clone `unchanged` (pull, same HEAD),
context `unchanged` (same text: `generatedAt` is NOT printed in the document), stubs `unchanged`, manifest written
(only `generatedAt`/`jobId` differ).

### 7.6 `src/lib/proc.ts` (SERVER)

```ts
export interface ProcOptions {
  cwd?: string; env?: NodeJS.ProcessEnv; signal?: AbortSignal; timeoutMs?: number;
  /** Called per output line (stdout + stderr, split on /\r\n|\r|\n/, trimmed of trailing spaces, empty dropped). */
  onLine?: (line: string) => void;
}
export interface ProcResult {
  code: number;              // exit code; 127 spawn failure; 124 timeout; 130 aborted
  stdout: string;            // stdout only, capped at 64 KiB
  tail: string[];            // last 20 lines of stdout+stderr, each cut to 300 chars
  durationMs: number; aborted: boolean; timedOut: boolean; spawnError?: string;   // e.g. 'ENOENT'
}
export type ProcRunner = (cmd: string, args: readonly string[], opts?: ProcOptions) => Promise<ProcResult>;
export const spawnCapture: ProcRunner;
```
`spawn(cmd, args, { cwd, env, shell: false, windowsHide: true, stdio: ['ignore', 'pipe', 'pipe'] })` (no `signal`
option: handle abort manually so `'close'` is awaited); abort / timeout → `kill()` then `kill('SIGKILL')` after
2 s; resolve on `'close'`, or 3 s after SIGKILL regardless. Never rejects. `'error'` before spawn → code 127,
`spawnError = err.code`.

| from | event | to |
|---|---|---|
| — | `start` (no job running) | `queued`, then `running` on the next microtask (`startedAt`) |
| — | `start` while one is queued/running | refused `{ ok: false, running }` |
| queued | `cancel` | `cancelled` (`finishedAt`, steps `cancelled`) |
| running | `cancel` | stays `running`, `cancelRequested: true`, signal aborted → `cancelling`; ends `cancelled` |

### 9.2 Paths

`mounts` = views with `dest !== null`, `sourceAbs !== null`, `state !== 'failed'`, sorted by `sourceAbs.length`
desc. `pathOf(abs)`: first mount where `abs === src` → `dest`, or `abs` starts with `src + '/'` or `src + '\\'` →

`pathOf`: `entryAbs`, `rootAbs`, `files[].abs` (so `rewriteLinks` targets become relative), `targets[*].abs`
(ctxman: links), local `root`/`target`, the eager clause. In dir mode the strings "the project root" become "this
directory" (skill install / clone instruction lead-ins).

### 9.3 Section order (dir mode)

1. Header: `# ${name}`, blank, `> ${sessionLine}`, `> This directory is the working root (\`${dir}\`). Relative
   paths below are relative to it; absolute paths point outside it. Read the referenced files and run the listed

3. `## Working directory map` (§9.4).
4. `## Primary repository` (only with a primary whose view state is not failed).

6. `## Skills` (every skill/remote-skill view; omitted when none).

### 9.4 Working directory map (exact)

A `text` fence. Rows: files first (contextFile `this file`; CLAUDE.md `loads this file`; AGENTS.md `points to this
file`; .gitignore `ignores the machine-specific paths below`), then group `repos/`, then one group per okf dataset

in segment order with note `how` + (` · primary`) + (` · ${trunc(description, 56)}` when non-blank). `how`:
