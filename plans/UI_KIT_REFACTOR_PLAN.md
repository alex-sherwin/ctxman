## 0. Summary, goals, non-goals

**Problem.** The UI grew in four rounds (P1-P7, Round 2, Round 3, Inflate v1/v2) and each round added its own copy of the same five things: a HUD label (uppercase 11 px, 26 copies of the 4-declaration recipe), a coloured status line keyed by `data-kind` (10 class families), an error paragraph (13 classes), an info/warn/danger banner (10 classes) and a "title · slug · description" entry line (11 families, 22 class names). The same happened in TSX: two draft banners, two `StatusLine`s, two `DiscardDialog`s, three Discover rows, six copies of the "draft text while focused" field pattern, six single-select chip groups hand-rolling `[...keys][0]`, five dialog footers with a `FORM_ID` submit button, and five Cmd/Ctrl+S listeners. Some kit exports have no caller (`Menu*`, `Switch`, `TextAreaField`, kit `Link`, kit `Breadcrumbs`, `Chip size`), some store exports only tests call (`addTag`, `removeTag`), a few component props are hacks around a missing kit prop (`RelationDialog.ModeMarker`), and eleven raw `--cyber-*` colours bypass `tokens.css`.

**Goals.**
1. One kit recipe per look: `ck-label`, `ck-status[data-kind]`, `ck-error`, `ck-notice[data-tone]`, `ck-loading`, `ck-entryline*`, each defined ONCE in `src/ui/kit/*.css`, used by React (kit component) and Astro (same class) alike. App and island CSS keep only placement and size; never colour-by-kind or label typography.
2. One component per job: `Status`, `ErrorText`, `Notice`, `Loading`, `ChipToggle`, `FormDialogFooter`, `EntryRow`, a single `DraftNotice`, a single `saveStatusView()`.
3. State where it belongs: derived values instead of effects (`MarkdownModal` reload, `RelationDialog` mode marker), one `useDraftField` hook for the six "draft while focused" states, one `useSaveShortcut` for the island Mod+S listeners, dead store actions removed.
4. Tokens for the eleven raw palette references and the repeated bar heights / hover tint / accent bar.
5. Consistent copy and variants: Cancel is `secondary` everywhere, Retry is `size="sm"` except inside an `EmptyState` action, destructive triggers are `ghost`, empty panel bodies use one compact `EmptyState`, open-in-new-tab is an `external` icon, glyph buttons (`↑ ↓ ×`) become icons.
6. A unit test that fails when a `ck-`/`cx-` class is defined but never used (or used but never defined), so the dead-selector list stays empty.

**Non-goals (binding).** No new features. No visual redesign (cybercore dark, Inter + Hack, information-dense layout stay; the pixel look of every page is meant to be the same or within a 1-2 px alignment tolerance). Islands keep their responsibilities and count (10 after Phase 8). No framework change, no CSS tooling. **No test id is renamed or removed** except `relation-mode` (never referenced by a spec); exactly ONE e2e assertion changes (Appendix A). No URL state change. No store split of `forge.ts` / `inflate.ts` (Deferred). No change to Phase 7/8 behaviour.

### 2.3 State ownership rules (restated, with the three fixes)

* URL carries page state (unchanged). Stores own loaded documents, drafts, save status, URL mirrors. Components own ONLY transient drafts: text being typed (`useDraftField`), an open dialog (`useState<EntryDialog | null>`), a pending confirm.
* A value that can be computed from state is computed in render, never synced by an effect (`MarkdownModal` reload moves into `save()`; `RelationDialog`'s `data-mode` becomes a prop).
* Effects are for external systems only: the SSR preview node (`DocEditor`), `document` listeners (`EntryTools`, `MarkdownTargets`), window shortcuts (`useSaveShortcut`), stores' `initX()` on mount.

## Gotchas for implementers

* `attrs` on `Modal`/`Notice`/`Status`/`EntryRow` is for `data-*` only; `aria-*` goes on the element the component renders for you (`role` prop) or stays on an inner element you own.
* `Notice role="none"` for lists that are not announcements (warnings lists), `role="alert"` only for conflicts/blocking, `role="status"` (default) for everything else; never nest live regions (a `Spinner` inside a `role="status"` element must be the decorative, label-less form).
* `useSaveShortcut` needs a stable callback: module-level store actions (`saveDoc`, `submit`) are stable; component closures use the `useRef` + `useEffect` latest-callback pattern from `CodeEditor.tsx:127-136` and pass `() => ref.current()`.
* `ChipToggle.onChange` is only called when the key changes, so `DocEditor`'s `leaveEdit` confirm cannot fire on the already-selected chip.
* `saveStatusView` must produce exactly the strings listed in Appendix A; the forge/inflate e2e specs compare them literally.
* `EntryRow` keeps the badge ORDER of the Forge row (title, slug, dataset, [refType], state, invalid, stale, tags); `forge.spec.ts:598` and `inflate.spec.ts:1106` look for `.ck-badge--ds` inside the row, nothing depends on position.
* `Panel.astro` `as="nav"`: Astro dynamic tags need `const Tag = as ?? 'section';` and `<Tag …>`; keep `aria-labelledby` on it.
* Do not touch `src/ui/shortcuts/**`, `src/lib/shortcuts.ts`, `src/styles/shortcuts.css`, the `data-shortcut-*` body attributes or the footer `?` button (Phase 8), nor the Files-before-Details order (Phase 7).
* `pnpm run test tests/unit/x.test.ts` (no `--`): pnpm 11 forwards the path literally with `--`.
