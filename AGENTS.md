# AGENTS.md

ctxman (context manager): a local-only Astro SSR app (Node backend, never deployed) that keeps knowledge, work items, skills and external references as files in a **data directory** (`CTXMAN_DATA_DIR`, required; the committed sample corpus is `tests/data/`), links them with typed **relations**, and assembles them into reusable **contexts** (evergreen link sets) for agentic coding sessions. **Context Inflate** (`/inflate`, dataset `recipe`) expands contexts plus extra items into one markdown document and manifest, OR (v2) into a **working directory** (symlinked / copied / cloned / worktree / downloaded material plus an `AGENTS.md` context file that links to it) for Claude Code, Codex or a generic agent; design in `tests/data/kb/ctxman/concepts/context-inflate.md`. An embedded **MCP server** (`POST /mcp`) exposes the same data to agents. In-browser editing is in `concepts/editing.md`, relations in `concepts/relations.md`, MCP in `concepts/mcp.md` (same folder).

**pnpm only** (never npm/npx/yarn; no `package-lock.json`). Node >= 24. Run the app with `pnpm run dev` (http://127.0.0.1:4321) after setting `CTXMAN_DATA_DIR` (shell variable or a `.env` file at the repo root, see `.env.example`; to try the sample corpus use `CTXMAN_DATA_DIR=tests/data`, but that edits the committed files).

## Data directory and environment

- `CTXMAN_DATA_DIR` is **required everywhere** (server, scripts, tests): the directory that holds `kb/ task/ reference/ context/ …`. There is no default. Relative values resolve against `process.cwd()`. `src/lib/data-dir.ts` (`resolveDataDir()` throws `DataDirError` `unset|missing|not-directory`; `dataDirStatus()`; `resolveServerOrigin()`) is the only reader; call it inside functions, never at module top level.
- `.env` at the repo root is honoured because the `dev`, `start`, `preview`, `add:*`, `check`, `check:data|okf|links|collections` and `fix:yaml-comments` scripts run `node --env-file-if-exists=.env`. `gen:schemas`, `check:schemas`, `build`, `typecheck`, lint, fmt and tests need no data dir.
- `CTXMAN_SERVER_ORIGIN` (optional, default `http://127.0.0.1:4321`) is the origin written into YAML modelines.
- `CTXMAN_AGENT_HOME` (optional) is the home directory the agent history import reads (`~/.claude` or `CLAUDE_CONFIG_DIR`, `~/.codex` or `CODEX_HOME`, `~/.copilot`, the VS Code `User` dirs via `XDG_CONFIG_HOME` / `APPDATA`); when set, those other variables are ignored and everything derives from it (`src/lib/agent-history/roots.ts#agentRoots`, the only reader). Tests and e2e servers set it to a fake home; unset = `os.homedir()`.
- Unset or unusable: scripts print the message and exit 2; the server answers 503 from `src/middleware.ts` (JSON `{error:'data-dir', message}` for `/api/*` and `/mcp*`, a self-contained HTML instructions page elsewhere) and re-checks every 2 s, so fixing the variable needs a restart (env is read at startup) but a created directory is picked up live.

- **OKF v0.2** (okf datasets): a bundle is `<ds>/<name>/index.md` (REQUIRED, the entry) + optional `log.md` (no create path writes one: templates, `/new`, `POST /api/entry`; only the MCP `append-log` tool creates it on request) + concept files. The root `index.md` is both the entry and the bundle navigation: frontmatter `okf_version: "0.2"` FIRST, then `type` (registry `okfType`), `name`, `description`, `state` for lifecycle datasets, `tags`, `links`, `stale_after`, provenance; its body is the entry content and may end with a `## Links` navigation section that `addConceptToIndex` keeps maintaining (it appends the section when absent and renames a legacy `## Concepts` heading). Optional key of every okf entry `index.md` (not concepts): `issueKey` = the key of the matching issue in an issue tracker (`PROJ-123`, `org/repo#42`; one word without whitespace, max 100: registry `ISSUE_KEY_PATTERN`, `issueKeySchema`), set in `/new/<ds>`, the Details dialog, `--issue-key`, PATCH and MCP; shown in the Details panel (`meta-issue-key`, with Copy) and as a list badge (`issue-key-badge`), searchable (SearchDoc `issueKey`, Fuse key) and on the Inflate meta line (`issue: \`KEY\``). Optional keys of entry and concept frontmatter: `index: false`(out of search, see Search tags) and`modified`(stamped by the DocEditor on every save: quoted UTC date-time to the second,`stampModified`; informational, freshness stays the mtime). Nested `index.md`and`log.md`have no frontmatter; every other`*.md`concept needs a non-empty`type`; `log.md`=`## YYYY-MM-DD`headings newest first;`stale_after`=`YYYY-MM-DD`; unknown keys are kept. There is NO `main.md`anywhere. This deviates from the OKF v0.2 reference skill, which keeps the root`index.md`free of concept semantics (documented in`kb/okf-format`). Check rules: `okf/missing-index`(error: no entry),`okf/index-frontmatter`(error:`okf_version`present and not`"0.2"`), `okf/index-version`(warning: absent). Inflate mode ids such as`inline-main` are stored in recipes and the recipe JSON Schema, so the ids stayed; only their labels say "entry".
- **Time tracking** (task, feature, bug, rca: registry `TIME_TRACKED_DATASETS`): optional `time` = array of ISO 8601 durations (`PT1H30M`, `P1D`; `durationSchema`) and optional `resolved` = an ISO 8601 date or date-time in any common form, kept as written (`resolvedSchema`; a YAML Date is accepted too). Rules in `src/lib/iso8601.ts`; the patcher writes `time` as a flow list after `tags` and quotes a date-time with seconds (the `timestamp` tag would read it back as a UTC Date). Edited by the Details dialog (TimeEditor: Enter adds a valid duration), PATCH and MCP `patch-entry` (`addTime` appends); a list row's Log time button adds one duration; the MetaPanel shows them with the total.
- **Search tags**: the frontmatter `tags` array of every okf markdown file (entry and concepts) gives the SearchDoc `tags`, each scalar value on its own (`search-index.ts#tagsOf`); Fuse matches them per element and `search-query.ts` keeps an exact tag index for `#tag` query tokens (widget store and MCP `search`). Frontmatter `index: false` (the boolean only; optional key of the okf entry and concept Types, not skills) keeps a file out of `buildSearchIndex`, and on an entry `index.md` its whole bundle; nothing else (lists, details, relations, pickers, Forge) reads the search index.
- **Relations**: an okf entry `index.md` may carry `links: [{dataset, slug, rel}]`, `rel` = child | related | depends-on (absent = related; one link per target; no self link; schema `entryLinksSchema`). The **project owns its children** (`rel: child` on the project; the Children panel, `?parent=` and `?project=` use them). Skills have no `links`. `ctxman:` links in any body are _mentions_ (shown as Mentions / Mentioned by). Incoming labels: Parent, Required by, Related, Mentioned by. Contexts are not graph edges (the "Linked from contexts" panel stays). Check rules `links/relation-target` (warning) and `links/relation-self` (error).
- **Links in prose**: inside a bundle `/x.md` (bundle root) or `./x.md` must resolve to an existing file (images too: `![a](now.png)` beside the `.md`); across entries ONLY `ctxman:<dataset>/<slug>` (a `/feature/x` path would be read as a bundle path). Missing `ctxman:` targets are warnings; the preview draws broken links dashed (`a.cx-link--broken`).
- **reference** `uri` (rules in `src/lib/remote-uri.ts`, never a generic URL validator): `remote-repo` = git URI (`git@host:org/repo.git`, `ssh://git@host/org/repo.git`, `https://host/org/repo[.git]`); `remote-skill` = git URI OR `https://…(.tar.gz|.tgz|.zip)` archive, shown with a derived `git`/`archive` badge. `local-repo` (a git repository) and `local-folder` (a plain folder) carry a `path` instead (`LOCAL_REFERENCE_TYPES` / `isLocalReferenceType` in the registry, `isLocalReference` in `schemas.ts`). `local-repo`, `local-folder` and `remote-repo` take an optional `folder` (`FOLDER_REFERENCE_TYPES`, `REFERENCE_FOLDER_PATTERN`: one folder name, a letter or digit first, then letters, digits, `. _ -`, max 100; serialized right after `subpath`; a remote skill rejects it): the folder Inflate places it under instead of the slug (`repos/<folder>`, `folders/<folder>`, and `{name}` of a clone directory; `itemDirName` in the catalog). Every type takes an optional markdown `info` (serialized last as a literal block, dropped when blank): the Info panel + pencil popup (`reference-info` target) on the detail page, a Monaco field in the DataForm, part of the search text, and inlined under the reference's item by Inflate (`render.ts#infoBody`: headings nested, `ctxman:` links resolved, other links left as written). Read/written through `src/lib/reference-io.ts` (CRUD API + DataForm; `listReferences()` also reports invalid files); a write is visible on the next request.
- **snippet** = a reusable piece of markdown (instructions you give every session, house rules): `name`, `description`, optional `tags`, required non-blank `markdown` (serialized last as a literal block, kept exactly as typed). No files, no bundle: the text is the data. Linkable, so a context or recipe includes it like any entry; Inflate has one mode for it (`inline`: the markdown under the item heading, headings nested, `ctxman:` links resolved) and nothing to place (material `none` only, no Place control, not counted as "not placed"). The detail page renders the markdown with Copy and a pencil popup (`snippet-markdown` target) and has Open in IDE (the `snippet/` folder with the file); the DataForm edits it in a Monaco field. Read/written through `src/lib/snippet-io.ts` (CRUD API + DataForm; `listSnippets()` also reports invalid files); the serializer is `src/lib/snippet-yaml.ts`.
- **skill** frontmatter is strict: `name` (== dir), `description`, optional `license`, `compatibility`, `metadata`, `allowed-tools`.
- **context** = pointers, never vendored content; no duplicate links, no link to `context` or `recipe`, `name` immutable. Always read/written through `src/lib/context-io.ts` (atomic write).
- **recipe** = a saved Context Inflate composition (`target` claude-code|codex|generic, `layout` grouped|flat, `contexts`, ad hoc `items`, `markdown` blocks, `overrides`, `order`, per-kind `defaults`, `preamble`, `output` = `{dir, contextFile, primary, allowNonEmpty, stubs}`; overrides and defaults also take `material` + `materialOptions`; an override of a `reference/<slug>` key also takes `edit`, the Editable flag); strict schema, `name` immutable, NOT linkable (`LINKABLE_DATASETS` excludes it). Always read/written through `src/lib/recipe-io.ts` (atomic write, key order fixed by `serializeRecipe`). Seven check warnings: `collections/recipe-context-missing`, `recipe-item-missing`, `recipe-override-stale`, `recipe-order-stale` (the last two only when every listed context exists and is valid), `recipe-output-dir-relative`, `recipe-material-invalid`, `recipe-primary-invalid`.
- **YAML data files** (reference, snippet, context, recipe) start with line 1 `# yaml-language-server: $schema=http://127.0.0.1:4321/api/schemas/<ds>` (the origin comes from `CTXMAN_SERVER_ORIGIN`; VS Code resolves it while ctxman runs). The io writers and `templates.ts` add it through `withSchemaComment(ds, body, origin)`; the serializers never do. The check `collections/yaml-schema-comment` (warning) accepts any loopback origin and port (127.0.0.1, localhost, [::1]) and an optional `.schema.json` suffix for that dataset, and flags anything else or a missing line; `pnpm run fix:yaml-comments` repairs. The in-browser YAML editors never show the line (they match schemas on the fake `file:///data/<ds>/…yaml` model path).
- Freshness = fs mtime (max over the entry dir) computed per request; `stale_after` reached = stale.
- Create entries with the scripts or the `/new/<ds>` forms, or clone an okf bundle (`⋯` Clone…, the clone API, MCP `clone-entry`); never copy folders by hand; finish with `pnpm run check` at 0 errors / 0 warnings.

## Tech (binding; the why is in italics)

- **Runtime**: Node 24 runs `.ts` directly, never transpile (scripts, e2e helpers). _Type stripping: erasable syntax only._ pnpm 11 (`packageManager`). Scripts that need the data dir run `node --env-file-if-exists=.env`.
- **TypeScript**: `typescript@next` 7.1 nightly (native `tsc`). _`@astrojs/ts-content-mapper` (tsconfig `contentMappers`) makes the same `tsc` check `.astro` files, so `astro check` is NOT used and `@astrojs/check` must not be installed._ `noUncheckedIndexedAccess` stays off (Astro's own components fail under it).
- **Framework**: Astro 7.4.0, `output: 'server'`, `@astrojs/node` standalone, `security.allowedDomains` = 127.0.0.1 and localhost (see Origin check). _No content collections: the data layer is plain `node:fs`, so a built server is always current._ Markdown via Sätteri, rendered per request in `src/lib/markdown.ts`: `satteri`'s `markdownToHtml` with the highlight and heading-id plugins exported by `@astrojs/markdown-satteri` plus two of ours (code block Copy wrapper; heading collection for `renderMarkdownDoc`), deliberately WITHOUT its image plugins (they turn a relative `<img>` into an `__ASTRO_IMAGE_` placeholder that only Astro's build-time asset pipeline resolves). `satteri` is a direct dependency pinned to the version `@astrojs/markdown-satteri` depends on: bump them together (`markdown-cache.test.ts` guards the output). Never add `@astrojs/markdown-remark`.
- **UI**: React 19 islands (exactly 12, all `client:only="react"`; never SSR an island): SearchWidget and Shortcuts (`Base.astro`, every page; Shortcuts = the `?` help dialog plus the `c` / `l` keys), Forge, Inflate, ToolsRunner, DocEditor (okf + skill detail and sub-doc pages), MarkdownTargets (`/context/<slug>`, `/recipe/<slug>`, `/reference/<slug>`), DataForm (reference/context/recipe `?edit=1` and `/new/<ds>`), EntryTools (okf/skill/reference detail and doc pages), NewEntryForm (`/new/<ds>` for okf + skill), EntryMenus (detail pages: the `⋯` menu portaled into the SSR `[data-entry-menu]` slot; the Clone (okf) and Delete actions), and ListTable (`/<ds>` lists; its data is NOT a prop: the page writes the rows as JSON into `<script type="application/json" id="ctxman-list-data">` via `serializeListData` and the island reads it on mount) + react-aria-components kit + vanilla CSS. Everything else is SSR Astro. Forge and Inflate bundle Monaco; the other islands load it lazily (`LazyCodeEditor`) or not at all.
- **Theme**: `cybercore-css` 0.3 (dark only) as base layer; Inter Variable + Hack self-hosted from npm (no CDN, no Google Fonts). Information-dense layout.
- **Editing**: Monaco (`monaco-editor` + `@monaco-editor/react`, loaded locally via Vite workers) for EVERY multi-line markdown/JSON/YAML input; plain `TextField` for single-line values. `monaco-yaml` 5.5.1 gives YAML editors diagnostics, hover and completion from `schemas/*.schema.json` (see Editor).
- **State**: nanostores + `@nanostores/react`; the URL carries all page state.
- **Validation**: `arktype` 2.2.8 is the ONLY validator (a runtime dependency; also in `vite.optimizeDeps.include`): Types in `src/datasets/schemas.ts` give runtime validation, TypeScript types and the JSON Schemas; zod is NOT a dependency of ours and importing it is banned by oxlint `no-restricted-imports` (it only exists as a transitive dependency of the MCP SDK).
- **MCP**: `@modelcontextprotocol/server` 2.3.1 (v2 SDK line, not `@modelcontextprotocol/sdk`); tools are registered with `McpServer.registerTool` whose `inputSchema` is an arktype Type (Standard Schema).
- **Other**: fuse.js 7 search; `yaml`; `mdast-util-from-markdown` 2.1 + `micromark-extension-gfm` 3 + `mdast-util-gfm` 3 (GFM markdown to an mdast tree that `src/lib/jira-markup.ts` walks itself: no unified/remark, no converter package; `@types/mdast` dev; in `optimizeDeps.include`); oxlint + oxfmt (`.oxlintrc.json`, `.oxfmtrc.json`); vitest 5; Playwright 1.64.
- New dependency: `pnpm add`, record it here. Add new client deps to `vite.optimizeDeps.include` in `astro.config.ts` (prevents mid-session dev reloads).

## Coding rules

- **TypeScript only.** Erasable syntax: no `enum`, `namespace` with values, constructor parameter properties, `import x = require`; use `as const` + unions. Relative imports carry the extension (`./x.ts`, `./X.tsx`); `import type` for types; `.ts`/`.tsx` never import `.astro`. Import CSS packages from CSS, not TS (TS 7 side-effect import check).
- **Layering of `src/lib`** (each file's header comment names its kind; THREE kinds, no file under `src/lib` imports `astro:*`): PURE (no fs; browser-safe), NODE (`node:fs` ok), SERVER (`http`, `run-script`, `ide`, `entries`, `mcp/*`: server only). Pages, API routes and `src/middleware.ts` import `astro` types and `astro:middleware` only. PURE: `text`, `object`, `list-sort-memory`, `clipboard`, `copy-formats`, `menu-popup`, `relations`, `shortcuts`, `file-tree`, `doc-toc`, `iso8601`, `search-query`, `jira-markup`, `frontmatter-patch`, `link-insert`, `reference-yaml`, `schema-comment`, `yaml-doc`, `names`, `reorder`, `json-schema` (scripts/tests only), `forms/*` (incl. `entry-form`), `datasets/schemas`, `datasets/validate`. NODE with fs: `data-dir`, `entry-index`, `entry-io`, `entry-create`, `entry-clone`, `atomic-write`, `doc-io`, `reference-io`, `schema-check`; `markdown` (Sätteri, memoized within a total html budget; `{memo, highlight}` options) and `skill-check` are NODE without fs calls. SERVER: `entries.ts` (everything pages, API and MCP read: lists, details, search index, relation graph), `http.ts`, `bundle-file.ts` (the raw file route), `lib/mcp/*`. In `src/lib/agent-history`: `types`, `parse-util`, `claude`, `codex`, `copilot-cli`, `vscode`, `query`, `errors`, `markdown` are PURE (browser-safe; the parsers are LineParsers fed one JSON line at a time and return a ParsedSession, markdown gets the inert transform injected); `roots` and `inert` (satteri's `markdownToMdast` + `links.ts`) are NODE without fs calls; `files`, `sources`, `sessions`, `plans`, `import` are NODE with fs, read-only on the agents' dirs (never write or follow a symlink there; a request names a key, never a path). In `src/lib/inflate`: `catalog`, `recipe`, `expand`, `material-plan` (also every type that crosses the inflate API) are PURE (the Inflate island may import only these); `markdown`, `render`, `pipeline` are NODE without fs calls of their own; `fs-sources`, `write`, `output-dir`, `material-exec`, `dir-plan` and `recipe-io.ts` are NODE with fs (`dir-plan` also imports `proc`, so scripts never do); `jobs.ts` and `src/lib/proc.ts` are SERVER. Never import fs/SERVER files from an island; no barrel `index.ts` there. Scripts import only `src/datasets/*` and PURE/NODE libs; tests may add SERVER libs; neither imports `astro:*`. `src/ui/editor` touches `self`/Monaco: import it only from `client:only` islands.
- **Validation**: call arktype only through `validate(schema, input)` / `assertValid(schema, input, what)` in `src/datasets/validate.ts`; it returns `{success, data}` or `{success: false, issues: ValidationIssue[]}` (`{path: PropertyKey[], message, code, kind}`, `kind` = `unknown-key` | `custom` (a narrow: duplicates, applicability) | `other`). It prunes `undefined`-valued keys first; custom narrows only run once the document is structurally valid; an unknown key's issue path is the key itself with message `Unrecognized key "x"`. Messages carry arktype's `(was "x")` suffix; `findings.ts#describeIssue` maps the wording (Required, invalid date, unknown key, stripped path prefix, friendly recipe-defaults text). Loose objects keep unknown keys; strict ones use `'+': 'reject'`. Never import zod and never call a Type directly. Tool input Types for MCP must stay JSON-Schema-expressible (no `.narrow`, no `string.date.parse`).
- **Read path (okf + skill)**: the DISK is the truth on every request; there is no content layer and no watcher. Lists, summaries, details' frontmatter, bodies, the relation graph and invalid-file reporting read through `entry-index.ts` (one scan, cached per entry dir by file `(mtimeMs, size)`, 200 ms memo; every write route calls `invalidateEntryIndex()`), so a PATCH, state change or create shows on the very next request and an invalid file is listed with its issues. Bodies are rendered per request by `renderMarkdown` (Sätteri; memo keyed by sha1 of the source, 256 entries) and then `rewriteRenderedHtml` (`<a href>` and `<img src>`: bundle `.md` -> doc routes, other bundle files -> `/<ds>/<slug>/file/<path>`, `ctxman:` -> entry routes, missing targets marked `cx-link--broken`). That rewrite is the browser view ONLY: Inflate never renders HTML and resolves links in the markdown itself (`inflate/markdown.ts#rewriteLinks`). The search index (`buildSearchIndex` in `entries.ts`) walks the bundles on disk (the entry `index.md` as the entry doc, every other `.md` except nested `index.md` and `log.md`). References are read through `reference-io.ts` (`listReferences` returns `{items, invalid}`), contexts and recipes through their io modules.
- **Origin check**: mutating routes call `checkOrigin` (`src/lib/http.ts`): no `Origin` passes; an Origin equal to `url.origin` passes; else protocol and port must match and either the hostnames are equal or both are loopback (127.0.0.1 / localhost / ::1), or the Origin equals the `Host` header; anything else is 403. `security.allowedDomains` in `astro.config.ts` makes the built node server trust the Host header (otherwise it rebuilds `Request.url` as `localhost` and refuses `Origin: http://127.0.0.1:4321`); `pnpm run test:prod` guards this.

- **Editor**: Monaco is mounted by `CodeEditor` (kit barrel: Forge, Inflate) or `LazyCodeEditor` (`React.lazy` with a same-size `testId` fallback: every other island); both take the same `CodeEditorProps`. Markdown models get link completion registered ONCE in `monaco-setup.ts` (`link-completion.ts` + pure `link-insert.ts`): `ctxman:` (target), `](` (destination), `[[` (whole link) and Ctrl+Space; not a bare `[`. "Insert link to entry…" is Mod+Alt+K (Monaco binds Mod+Shift+K to delete line) plus a context-menu item, opened through `useInsertLink`, which focuses the editor BEFORE the picker mounts so react-aria restores focus into it. A YAML editor of reference/context/recipe passes `schemaDataset`: the model path becomes `file:///data/<ds>/<testId>-<id>.yaml`, which the schema `fileMatch` needs (`inmemory://` resolves nothing); monaco-yaml markers (owner `yaml`) coexist with the `ctxman` markers, and only `YamlIssue`s with `!coveredBySchema` are passed as `markers`. monaco-yaml needs three shims together (remove none): the `createWebWorker` adapter in `monaco-setup.ts`, the Vite alias for `monaco-editor/esm/vs/editor/editor.worker.js` and the `monaco-yaml > …` entries in `optimizeDeps.include`. Schemas are imported statically. After changing the Type of a yaml dataset run `pnpm run gen:schemas` (`check:schemas` is the gate).
- **Save model of in-browser editing**: explicit Save only (button or Cmd/Ctrl+S; no autosave). IDE edits show on the next browser reload (nothing watches the data dir). A successful write reloads the page itself, in dev and in a built server alike: a doc save and the state select after ~150 ms (`RELOAD_AFTER_SAVE_MS` in `src/stores/doc-editor.ts`, `STATE_RELOAD_MS` in `src/scripts/shell.ts`), the EntryTools dialogs at once (`src/ui/entry/after-write.ts`), `data-form.ts` navigates directly; a doc save returns to preview, dims it (`data-stale`) and remembers "Saved" in sessionStorage (`last-save`). Doc saves send `ifUnmodifiedSince`; a 409 opens the ConflictDialog (Keep editing / Load disk version / Overwrite). Validator findings show after a save, never block it.
- **Drafts**: unsaved text of DocEditor, MarkdownModal, Forge and Inflate is mirrored to **localStorage** (`draft-backup.ts`, key prefix `ctxman:draft:`, 14-day TTL, `{text, base, savedAt}`) and restored after any reload with a "Restored unsaved changes" banner (`DraftNotice`, one component in `src/ui/edit` for DocEditor, MarkdownModal, Forge and Inflate; `data-stale` when the file changed on disk since: saving then overwrites it). MarkdownModal, Forge and Inflate have NO native `beforeunload` prompt (in-app discard/confirm dialogs and the Forge/Inflate `popstate` confirm stay). The DocEditor guards unsaved text on every way out: the Preview toggle, Cancel, Back/Forward (undone with `pushState`, then asked) and a click on any link (`leave-link.ts`, window bubble-phase click listener) go through `requestLeave` and the in-app "Discard unsaved changes?" dialog (`$docLeave`); everything else that unloads the page gets the browser prompt (`useUnsavedGuard`; `confirmLeave` calls `allowUnload()` before following a link so the browser does not ask twice). DataForm and NewEntryForm (no persistence) keep `useUnsavedGuard` (+ `unload-guard.ts`: stores call `allowUnload()` right before a post-write `location.assign`/`reload`, so the happy path never shows the browser's leave prompt).
- **Shared editing layer**: `src/ui/edit/` (SaveBar, ConflictDialog, TagEditor, TimeEditor, YamlIssues, `useViewportFill` (a full-page editor box ends at the viewport bottom: it measures `--fill-top`/`--fill-after` for the CSS height; DocEditor and the DataForm YAML view; while the DocEditor is open the details column scrolls inside), `api.ts` `getJson`/`sendJson` that never throw, `draft-backup`, `last-save`, `useUnsavedGuard`, `DiscardDialog`, `useDraftField`, `useSaveShortcut` (capture-phase Mod+S, the one island listener; the Forge/Inflate stores keep their own), `DraftNotice`, `saveStatusView`/`failureText`, `edit.css`) is browser-only with NO Monaco; import its files and kit parts by file. `src/lib/names.ts` holds `nameProblem` and the tag rule. `ensureEntries`/`ensureAllEntries`/`loadAllEntries` in `src/stores/entries.ts` feed pickers and completion; `parseEditUrl` in `url-state.ts` reads `edit=1` and `view`. `$docEditing` (doc-editor store: a DocEditor is mounted AND in edit mode, not just `?edit=1`, which the reference form uses too) is what locks EntryTools buttons and the state selects (`Leave the editor first`) and holds back their post-write reload.
- **URL is state**: anything that selects data lives in the URL. List: `q`, repeated `state`/`tag`, `sort` (modified|name, + state for lifecycle datasets, type|owner for reference, links for context, target|contexts for recipe, + time for task/feature/bug/rca: `listSortsFor`), `dir` (asc|desc, omitted when `defaultSortDir`), `type` (reference), `project` (children of a project). Search: `search=1&sq=<query>&in=<ds,ds>` (never `q`). Forge: `context`, `dataset` (a linkable dataset or `all`), `q`, `state`, `tag`. Inflate: `recipe` (slug or `new`), `view` (compose|preview|run), `dataset` (ad hoc tab, or `all`), `q`, `job` (only with `view=run`), `paths` (`absolute`; relative is the default). Tools: `add`. `/new/<ds>`: `parent`. Detail and doc pages: `edit=1` (the DocEditor sets and removes it with `pushState`: every switch between preview and edit, a save included, is a history entry and Back/Forward switch modes; Back out of unsaved text asks first); yaml datasets add `view` (form|yaml). Use `src/lib/url-state.ts`. Not URL state: unsaved edits, action results, ephemeral UI (open dialogs), view preferences (the list table layout in localStorage; the remembered list sort, a cookie, only ever redirects to a URL that carries it).
- **nanostores pattern**: URL-synced stores read `location` in `onMount`; actions are plain functions that set stores and call `history.pushState/replaceState`; `popstate` re-reads the URL and never writes history; time comes from `$now`, not `Date.now()` in render; `useState` only for local transient drafts.
- **React**: follow the Rules of React (pure render, no setState in effects, no ref reads in render, no mutation). React Compiler is off, but oxlint `react-hooks-js/*` rules enforce compatibility. A prop named `children` is overwritten by Astro's slot children: pass lists as `childEntries`.
- **API**: JSON only via `src/lib/http.ts` (`json`, `apiError`, `readJson`): `cache-control: no-store`, errors `{error, message, issues?}`; mutating routes answer 415 (not JSON), 403 (Origin check above), 400 (bad body), 404, 409 (exists); `DELETE` routes answer 204 without a body (no JSON content type needed), except `DELETE /api/doc/...` (200 `{path, url, warnings}`: the links left pointing at the removed file). `PATCH /api/entry/...` edits only the given top-level keys by range-based text splicing (`frontmatter-patch.ts`, every other byte stays), under a per-file lock (`withFileLock`), and NEVER writes frontmatter that fails the dataset schema (400 `invalid`, nothing written; 409 `conflict` when `ifUnmodifiedSince` differs from the file mtime; 422 `invalid-file` when the file's frontmatter is unusable). `PUT /api/doc/...` is the opposite: it always saves, returns validator `warnings` (incl. `links/*`), 409 `conflict` (body carries the CURRENT `lastModified`), 413 above 512 KB, 422 `not-text`, and never creates a file; `POST /api/doc/...` creates a concept (409 `exists`). `POST /api/ide/open` answers 501 `ide-not-found` / 500 `ide-spawn-failed`. `GET /api/schemas/:dataset[.schema.json]` answers 404 `unknown-dataset` / 500 `schema-missing`. `/api/inflate/render`, `/write`, `/plan`, `/run` are POST-only and need the same checks; `/write` answers 400 `bad-path` / `write-failed`; `/run` answers 400 `no-dir` / `bad-dir` / `dir-not-directory`, 409 `dir-not-empty` / `manifest-invalid` / `busy`; `/jobs/:id` 400 `bad-id` / 404 `not-found`; `/jobs/:id/cancel` 409 `not-running`. `/api/scripts/:name` runs only `src/lib/scripts-allowlist.ts` entries, answers 200 even when the script exits non-zero, 404 for an unknown name. Every route answers 503 `data-dir` while the data dir is unusable (middleware).
- **MCP** (`src/pages/mcp.ts` -> `src/lib/mcp/http.ts`): `POST /mcp`, Streamable HTTP, stateless (one `McpServer` per request, no sessions), served by the same Astro server. `GET`/`DELETE` answer the SDK's 405; a wrong content type is 415 and a 2025-era POST without `Accept: application/json, text/event-stream` 406. The Host header must be loopback and an Origin, when present, loopback (403 otherwise; no Origin passes). Tools: `search`, `list-datasets`, `list-entries`, `get-entry`, `list-bundle-files`, `read-bundle-file`, `get-context`, `render-recipe`, `check-data` (read) and `create-entry`, `clone-entry`, `patch-entry`, `append-context-links`, `append-log` (write; immediate, last write wins). Resources: `ctxman://{dataset}/{slug}` and `ctxman://{dataset}/{slug}/doc/{+path}`. Tools reuse the same lib modules as the API (never the API over HTTP) and return markdown plus `structuredContent`. Client setup and the full tool table: `concepts/mcp.md`.
- **Cross-platform**: OS-level work uses `node:fs`/`node:path`/`node:util`; spawn `process.execPath` with argv, `shell: false`; no bash/sh scripts. The exceptions: the IDE launcher (`src/lib/ide.ts`) spawns the user's `code` command with `shell: false`, detached (only a win32 `.cmd`/`.bat` goes through `cmd.exe /d /s /c`), and Inflate runs spawn `git`, `tar`, `unzip` through `src/lib/proc.ts` (argv, `shell: false`, never a shell string).
- **Files under the data dir**: every path that comes from a request goes through `safeJoin` / `resolveBundleFile` (`src/lib/bundles.ts`: no `..`, no absolute path, realpath must stay inside the entry dir); writes are atomic (`writeFileAtomic` in `atomic-write.ts`: dot-prefixed temp file in the same dir, then `rename`). The IDE opens only an entry dir (or the data dir for yaml datasets) with a file inside it, never a file alone, and the request never chooses the executable.

## Testing rules

- Unit (`tests/unit`): PURE/NODE/SERVER libs and stores only (no `astro:*`). `tests/unit/setup.ts` (vitest `setupFiles`) pins `CTXMAN_DATA_DIR` to an EMPTY temp dir (and `CTXMAN_SERVER_ORIGIN` to the default) for every test file, so a test that forgets its own dir sees an empty corpus, never the repo; it pins `CTXMAN_AGENT_HOME` to another empty temp dir, so no test reads the real agent histories (tests that want sessions call `buildAgentHome(dir)` from `tests/fixtures/agent-home.ts` and pass `{CTXMAN_AGENT_HOME: dir}` as the env). Build fixtures in OS temp dirs (`tests/unit/fixtures/data-fixtures.ts`); for realistic data call `copyCorpus()` (`tests/unit/fixtures/corpus.ts`: copies `tests/data` into a temp dir; `cleanupCorpus()` in `afterEach`). NEVER read or write `tests/data` (or any real data dir) directly (reading the committed `schemas/` is fine); CLIs run with `CTXMAN_DATA_DIR` set. New lib behavior or bugfix = new test.
- Prod smoke (`tests/prod-smoke.ts`, `pnpm run test:prod` after `pnpm run build`): a framework-free check of the BUILT server (origin check, saves, schemas, `/mcp`); keep it green when touching origin checks, middleware, `astro.config.ts` or `/mcp`.

- E2E (`tests/e2e`): Playwright against the BUILT app, `fullyParallel`, workers = half the cores, 2..8 (`--workers N`; measured: 360 tests in about 36 s on 7 workers, down from 402 s serial on `astro dev`). `globalSetup` rebuilds `dist/` when it is older than `src`/config (`E2E_BUILD=auto|always|never`) and creates the shared read-only git fixture (`.tmp/e2e/git`). Specs rely on seed entry names and counts (`kb/ctxman`, `context/ctxman-dev`, `recipe/ctxman-dev-brief`, `project/ctxman-v1` with 11 children, 4 seed tasks): do not rename or add to seeds without updating specs; `e2e-*` names are reserved for specs (a spec that adds children uses its own `e2e-*` project); never write a seed entry (copy it, e.g. `createRecipeCopy`). Remove okf/skill entries through the API (`deleteEntries(request, ['task/e2e-x'])` in `helpers.ts`, `DELETE /api/entry`), never with `rmSync` alone: the server memoizes its entry index for 200 ms and only a write route drops the memo, so the next test of the worker would still list the removed entry (the old list-table flake). ## Caveats

- **No content layer, no watcher**: every read goes to the filesystem, so `pnpm run dev` and a built `pnpm run start` behave the same for data. A built server needs a rebuild only for CODE changes, never for new entries. Edits made in the IDE or by a script appear after a browser reload (nothing pushes them). `astro dev` still reloads for CODE changes (Vite HMR), and the first browser connection after start gets one reload. The e2e suite runs the BUILT server, so none of that dev behaviour reaches a test.
- **After an in-browser write** (doc save, state select, and the EntryTools dialogs: Details, relations, create, Add to context) the page reloads itself in both modes (~150 ms for a doc save and the state select, at once for the EntryTools dialogs); `data-form.ts` navigates directly. There is no settle reload, no sessionStorage reload counter and no 2 s fallback. Tools output survives a reload via `sessionStorage`.
- A saved doc with unparsable frontmatter is allowed on purpose for the doc editor (warnings only): nothing breaks at runtime, the entry shows an "invalid" banner and is listed flagged, and `pnpm run check:okf` names the file. The frontmatter PATCH can never write such a file. An invalid `reference/*.yaml` is listed flagged but its detail page is a 404 until fixed.
- **`CTXMAN_DATA_DIR` is required** (see Data directory and environment). `pnpm run build` and `typecheck` do not need it; `pnpm run start`, `dev`, the add and check scripts do. In tests it is pinned by `tests/unit/setup.ts` and by the e2e/prod-smoke runners.
- **Open in IDE**: the command is `CTXMAN_IDE_COMMAND` (a name looked up in PATH, or a path; set but missing = 501, no fallback), else `code` in PATH, else the usual VS Code install locations (win32: PATHEXT, `code.cmd`). It is run as `<command> <entry dir> <file>` without flags (a snippet: `<data dir>/snippet` and its yaml file; the other yaml datasets: the data dir and the file); `{ dir }` (a directory with a readable `.ctxman-inflate.json`) runs `<command> <dir>`. The Windows `.cmd` path is untested on a real Windows host.
- **YAML modelines** resolve only while ctxman runs at `CTXMAN_SERVER_ORIGIN` (default `http://127.0.0.1:4321`); the check accepts any loopback origin/port, so a file written for another port still passes.
- **MCP** is unauthenticated and loopback-only by design (Host/Origin validation); write tools change files immediately with no `ifUnmodifiedSince`. Keep results compact (Claude Code warns above 10k tokens and caps at 25k): lists default to 20, bodies over 50 KB are truncated with a note.
- Stuck or looping dev reloads, "new dependency" errors: stop the server and `rm -rf node_modules/.vite/deps`.
- Freshness is fs mtime, so `git checkout`/clone resets "modified" times.
- **Agent history import** (concepts/agent-history.md): read-only on `~/.claude`, `~/.codex`, `~/.copilot` and the VS Code storage; the formats are undocumented and observed (Oct 2026), so every parser skips what it does not know. Imported files are `type: agent-session` / `type: plan` with `index: false` (their text never enters search: the widget and MCP `search`; they still show in the Files panel, `## Links` (the title only: the entry `index.md` is searchable) and Inflate), raw HTML escaped and bundle / `ctxman:` / `javascript:` links neutralized, so an import adds no `links/*` finding. A session body may be up to about 1.5 MB, larger than the 512 KB the doc editor (`GET|PUT /api/doc`) opens: such a file renders but its Edit answers 413. Memory: a detail streams the session file one line at a time (`files.ts#jsonLineStream` / `byteLineStream`; VS Code attachments are cut out of a big line before it is parsed), listing caches hold summaries only (their strings detached with `ownString`), and previews render with `renderMarkdown(body, {memo: false, highlight: false})` (Shiki's regex engine keeps the memory a big render grew it to); never read a whole session file into a string, and keep anything cached small.
- **Inflate**: the document is generated on request from the files on disk. Paths in it are absolute and machine specific. Only an `eager` pointer uses a bare `@path`; every other path is backticked (a markdown link with a backticked text in a working-directory document) so nothing is force-loaded. Brief quality: in a document, and for an item that is not placed, every okf kind defaults to `inline-main` (a placed item defaults to `summary`, "Summary + links", and a placed skill to `pointer`, "Link": `modesForPlacement`); an inline okf item also prints its `description` when the body lacks it; empty template headings are dropped (`dropEmptySections`); markdown blocks nest under their group and are titled by their first heading; a link that does not resolve adds an `unresolved-link` warning. `shiftHeadings` handles ATX headings only. `/api/inflate/write` takes an absolute `.md` path outside `node_modules`, `.git` and the data dir (home is NOT required); the UI default is `out/<recipe>.md`. Clones in the generated commands go to `repos/<name>` (option `cloneDir`, full history unless `shallow`), remote skill downloads use `.ctxman/tmp/` inside the target project; when the document lists repositories its header says to run their commands from their own directory. Output over 512 KB adds a `large-output` warning. Stale overrides and order keys are only warnings until "Prune stale" removes them; removing a context, item or block in the UI prunes automatically.
- **Inflate into a directory** (`output.dir`, or the run-override `dir`; absolute or `~/…`): `POST /api/inflate/plan` (dry run) -> `/run` (202 job, ONE run at a time, 409 `busy`) -> the UI polls `GET /api/inflate/jobs/:id` every 500 ms. Jobs live in memory (last 20, lost on a server restart; `view=run&job=<id>` resumes after a reload). Every item answers Place (its `material`, resolved BEFORE the mode) then the mode; placed = a directory is set and the material is not `none`. Materials: okf and skill symlink (default) | copy at `<ds>/<slug>` / `<skillsDir>/<name>`, local-repo symlink (default) | worktree | copy and remote-repo clone (default) at `repos/<name>`, local-folder symlink (default) | copy at `folders/<name>` (`<name>` = the reference `folder`, else the slug), remote-skill install (a git clone or an archive download), or `none` ("Don't place"). Clones fetch the full history by default (`cloneDepth` 0, "Full"); material options `branch` and `newBranch` (clone, worktree: create that branch for the work, from Branch; a re-run of a clone on it only fetches, never pulls). A **worktree** is `git -C <repo> worktree add` (new branch / branch / detached), left as it is by later runs and removed only by `git worktree remove` without `--force` (local changes are kept). `output.primary` is one such repo (clone, symlink or worktree; never a local-folder: not a git repository); repositories and local folders also carry Editable (`isEditEligible`: symlinked or unplaced local-repo or local-folder, local-repo worktree, cloned remote-repo; default on for the valid primary; recipe override `edit` or run override `items[key].edit`, both only on `reference/` keys). Run overrides go through the pure `applyRunOverrides` BEFORE expansion. A run writes the context file (`AGENTS.md` by default, `output.contextFile` or the run override renames it), stubs (`AGENTS.md`, any target, only when the context file has another name; `.gitignore`; only when absent or unedited) and `.ctxman-inflate.json`, the record of what ctxman owns there. No `CLAUDE.md` is written for any target (Claude Code reads `AGENTS.md`); a recipe's old `output.stubs.claudeMd` is still valid but ignored and dropped on the next save, and an old directory's recorded `CLAUDE.md` stub (manifest role `claude-md`, still parsed) is a stale path: removed when unedited, kept, reported and dropped from the manifest when edited. Over a directory made with the old `LLM_CONTEXT.md` default, that file is removed as stale (when unedited) and the recorded, unedited `AGENTS.md` stub is replaced; an edited stub or a foreign `AGENTS.md` fails the `context` step ("move it away or choose another context file name"), and the dry run warns first (`context-file-exists`). The context document tells the agent to `cd` into `repos/<name>/` (or `folders/<name>/`) for git, build and test commands and to start there, the primary first.
- **Inflate directory safety**: `dir` must be outside the repo and the data dir (and not contain them), not a filesystem root or `$HOME`, no `node_modules`/`.git` segment; a non-empty dir needs a ctxman manifest or `allowNonEmpty`. A re-run deletes or replaces ONLY paths in the previous manifest that are still what ctxman created: clones with local or unpushed changes (also commits no remote-tracking ref holds: a work branch without upstream, a detached HEAD; `git rev-list HEAD --branches --not --remotes`), worktrees git refuses to remove (local changes) or whose detached commits no ref holds, edited stubs and retyped paths are kept and reported; symlinks are unlinked, never followed; every step path goes through `safeJoin` plus a realpath check. `git`, `tar` (bsdtar; `unzip` fallback) are system tools: a missing one demotes only the items needing it to `none` with a `tool-missing` warning. Git runs with `GIT_TERMINAL_PROMPT=0` and ssh BatchMode. Directory links are junctions on Windows, which is untested.
