# AGENTS.md

ctxman (context manager): a local-only Astro SSR app (Node backend, never deployed) that keeps knowledge, work items, skills and external references as files under `data/`, links them with typed **relations**, and assembles them into reusable **contexts** (evergreen link sets) for agentic coding sessions. **Context Inflate** (`/inflate`, dataset `recipe`) expands contexts plus extra items into one markdown document and manifest, OR (v2) into a **working directory** (symlinked / copied / cloned / installed material plus `LLM_CONTEXT.md`) for Claude Code, Codex or a generic agent; design in `data/kb/ctxman/concepts/context-inflate.md`. In-browser editing is in `concepts/editing.md`, relations in `concepts/relations.md` (same folder).

**pnpm only** (never npm/npx/yarn; no `package-lock.json`). Node >= 24. Run the app with `pnpm run dev` (http://127.0.0.1:4321).

Routes: `/` dashboard, `/<ds>` list (`/recipe` too; `?project=<slug>` = the children of that project), `/<ds>/<slug>` detail, `/<ds>/<slug>/doc/<path>` (okf only, no `.md`; a `….md` URL 301s to it; a missing concept path of an existing bundle offers "Create this file"), `/new/<ds>` (create form for ALL 11 datasets; `?parent=<project>` prefills "Part of project"), `/forge` (build contexts), `/inflate` (compose recipes, generate the document, or run it into a working directory: `view=run`), `/tools` (run allowlisted scripts; its Add Entry panel links to `/new/<ds>`), `/search` (302 to `/?search=1&sq=&in=`), 404. Edit mode = same URL plus `?edit=1`: okf and skill pages switch Preview to a Monaco source editor (DocEditor); reference, context and recipe pages swap the main column for the DataForm (`view=form|yaml`). okf and skill detail pages have a header state select (lifecycle datasets), "Add to context", a Details panel `Edit` (frontmatter dialog), Links to / Linked from panels, a Children panel on projects, a Files panel `+ New concept` (okf) and an invalid-file banner; reference pages get "Add to context" and Linked from; lists and the dashboard flag invalid files. Context and recipe pages have pencil buttons for markdown popups. Rows are whole-row links. Global search modal on every page (Cmd/Ctrl+K).

API (`src/pages/api`): `GET /api/search-index.json`; `GET /api/entries?dataset=`; `GET|PUT|DELETE /api/context/:slug`, `POST /api/context`, `POST /api/context/:slug/links` (append `{links}`, answers `added`/`skipped`); `GET|PUT|DELETE /api/recipe/:slug`, `POST /api/recipe`; `GET|PUT|DELETE /api/reference/:slug`, `POST /api/reference`; `GET|PATCH /api/entry/:ds/:slug` (okf + skill frontmatter: `state title description tags stale_after status links addLinks removeLinks ifUnmodifiedSince`); `POST /api/entry/:ds` (create, `{name, description, title?, state?, tags?, parent?}`, `parent` = a project that gets the child link); `GET|PUT|POST /api/doc/<ds>/<slug>/<...path>` (read / save one existing `.md` / create a concept: also adds the `index.md` line and the `log.md` entry); `GET|POST /api/ide/open`; `GET /api/schemas/:dataset`; `POST /api/inflate/{render,write,plan,run}`, `GET /api/inflate/jobs/:id`, `POST /api/inflate/jobs/:id/cancel`; `POST /api/scripts/:name`.

## Datasets (11; `name` == dir/file stem == slug == collection id; `^[a-z0-9]+(-[a-z0-9]+)*$`, max 64)

| id                     | kind               | entry file (under `data/`) | `state` (kebab-case; first = default)                                                                             |
| ---------------------- | ------------------ | -------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| kb, rca                | okf bundle         | `<id>/<name>/main.md`      | none                                                                                                              |
| idea                   | okf bundle         | `idea/<name>/main.md`      | pending, in-progress, complete, abandoned                                                                         |
| task, feature, project | okf bundle         | `<id>/<name>/main.md`      | pending, in-progress, complete, wont-do                                                                           |
| bug                    | okf bundle         | `bug/<name>/main.md`       | pending, in-progress, fixed, wont-fix                                                                             |
| skill                  | agentskills.io dir | `skill/<name>/SKILL.md`    | none                                                                                                              |
| reference              | yaml               | `reference/<name>.yaml`    | none; `type` local-repo / remote-repo / remote-skill (uri: git, or https archive for skills), `owner` me / not-me |
| context                | yaml               | `context/<name>.yaml`      | none; `links: [{dataset, slug, notes?}]`                                                                          |
| recipe                 | yaml               | `recipe/<name>.yaml`       | none; contexts, items, overrides, order, markdown, preamble (+ `target`, `layout`, `defaults`, `output`)          |

- **OKF v0.2** (okf datasets): root `index.md` frontmatter is ONLY `okf_version: "0.2"`; nested `index.md` and `log.md` have no frontmatter; `main.md` needs `type` (registry `okfType`), `name`, `description`, plus `state` for lifecycle datasets; every other `*.md` concept needs a non-empty `type`; `log.md` = `## YYYY-MM-DD` headings newest first; `stale_after` = `YYYY-MM-DD`; unknown keys are kept.
- **Relations**: an okf `main.md` may carry `links: [{dataset, slug, rel}]`, `rel` = child | related | depends-on (absent = related; one link per target; no self link; schema `entryLinksSchema`). The **project owns its children** (`rel: child` on the project; the Children panel, `?parent=` and `?project=` use them). Skills have no `links`. `ctxman:` links in any body are _mentions_ (shown as Mentions / Mentioned by). Incoming labels: Parent, Required by, Related, Mentioned by. Contexts are not graph edges (the "Linked from contexts" panel stays). Check rules `links/relation-target` (warning) and `links/relation-self` (error).
- **Links in prose**: inside a bundle `/x.md` (bundle root) or `./x.md` must resolve to an existing file; across entries ONLY `ctxman:<dataset>/<slug>` (a `/feature/x` path would be read as a bundle path). Missing `ctxman:` targets are warnings; the preview draws broken links dashed (`a.cx-link--broken`).
- **reference** `uri` (rules in `src/lib/remote-uri.ts`, never `z.url()`): `remote-repo` = git URI (`git@host:org/repo.git`, `ssh://git@host/org/repo.git`, `https://host/org/repo[.git]`); `remote-skill` = git URI OR `https://…(.tar.gz|.tgz|.zip)` archive, shown with a derived `git`/`archive` badge. Read/written through `src/lib/reference-io.ts` (CRUD API + DataForm) but keeps its glob loader WITH watcher (SSR lists lag a write by ~0.6 s).
- **skill** frontmatter is strict: `name` (== dir), `description`, optional `license`, `compatibility`, `metadata`, `allowed-tools`.
- **context** = pointers, never vendored content; no duplicate links, no link to `context` or `recipe`, `name` immutable. Always read/written through `src/lib/context-io.ts` (atomic write), NEVER `getCollection('context')`.
- **recipe** = a saved Context Inflate composition (`target` claude-code|codex|generic, `layout` grouped|flat, `contexts`, ad hoc `items`, `markdown` blocks, `overrides`, `order`, per-kind `defaults`, `preamble`, `output` = `{dir, contextFile, primary, allowNonEmpty, stubs}`; overrides and defaults also take `material` + `materialOptions`); strict schema, `name` immutable, NOT linkable (`LINKABLE_DATASETS` excludes it). Always read/written through `src/lib/recipe-io.ts` (atomic write, key order fixed by `serializeRecipe`), NEVER `getCollection('recipe')`. Seven check warnings: `collections/recipe-context-missing`, `recipe-item-missing`, `recipe-override-stale`, `recipe-order-stale` (the last two only when every listed context exists and is valid), `recipe-output-dir-relative`, `recipe-material-invalid`, `recipe-primary-invalid`.
- **YAML data files** (reference, context, recipe) start with line 1 `# yaml-language-server: $schema=../../schemas/<ds>.schema.json`. The io writers and `templates.ts` add it through `withSchemaComment`; the serializers never do. Missing/wrong = warning `collections/yaml-schema-comment`; `pnpm run fix:yaml-comments` repairs. The relative path only resolves for the default `./data`.
- Freshness = fs mtime (max over the entry dir) computed per request; `stale_after` reached = stale.
- Create entries with the scripts or the `/new/<ds>` forms (never copy folders); finish with `pnpm run check` at 0 errors / 0 warnings.

## Tech (binding; the why is in italics)

- **Runtime**: Node 24 runs `.ts` directly, never transpile (scripts, e2e helpers). _Type stripping: erasable syntax only._ pnpm 11 (`packageManager`).
- **TypeScript**: `typescript@next` 7.1 nightly (native `tsc`). _`@astrojs/ts-content-mapper` (tsconfig `contentMappers`) makes the same `tsc` check `.astro` files, so `astro check` is NOT used and `@astrojs/check` must not be installed._ `noUncheckedIndexedAccess` stays off (Astro's own components fail under it).
- **Framework**: Astro 7.4.0, `output: 'server'`, `@astrojs/node` standalone, content collections for every dataset. Markdown via Satteri (`@astrojs/markdown-satteri`); never add `@astrojs/markdown-remark`.
- **UI**: React 19 islands (exactly 9, all `client:only="react"`): SearchWidget (`Base.astro`, every page), Forge, Inflate, ToolsRunner, DocEditor (okf + skill detail and sub-doc pages), MarkdownTargets (`/context/<slug>`, `/recipe/<slug>`), DataForm (reference/context/recipe `?edit=1` and `/new/<ds>`), EntryTools (okf/skill/reference detail and doc pages), NewEntryForm (`/new/<ds>` for okf + skill) + react-aria-components kit + vanilla CSS. Everything else is SSR Astro. Forge and Inflate bundle Monaco; the other islands load it lazily (`LazyCodeEditor`) or not at all.
- **Theme**: `cybercore-css` 0.3 (dark only) as base layer; Inter Variable + Hack self-hosted from npm (no CDN, no Google Fonts). Information-dense layout.
- **Editing**: Monaco (`monaco-editor` + `@monaco-editor/react`, loaded locally via Vite workers) for EVERY multi-line markdown/JSON/YAML input; plain `TextField` for single-line values. `monaco-yaml` 5.5.1 gives YAML editors diagnostics, hover and completion from `schemas/*.schema.json` (see Editor).
- **State**: nanostores + `@nanostores/react`; the URL carries all page state.
- **Other**: zod 4 imported from `zod`, not `astro:content` (_so Node scripts share the schemas_; zod is the only runtime validator); `arktype` 2.2.8 (devDependency: models in `src/datasets/arktypes.ts` exist only to generate `schemas/*.json`, never imported by pages, API routes or islands; okf `links` has no arktype mirror); fuse.js 7 search; `yaml`; oxlint + oxfmt (`.oxlintrc.json`, `.oxfmtrc.json`); vitest 5; Playwright 1.64.
- New dependency: `pnpm add`, record it here. Add new client deps to `vite.optimizeDeps.include` in `astro.config.ts` (prevents mid-session dev reloads).

## Coding rules

- **TypeScript only.** Erasable syntax: no `enum`, `namespace` with values, constructor parameter properties, `import x = require`; use `as const` + unions. Relative imports carry the extension (`./x.ts`, `./X.tsx`); `import type` for types; `.ts`/`.tsx` never import `.astro`. Import CSS packages from CSS, not TS (TS 7 side-effect import check).
- **Layering of `src/lib`** (each file's header comment names its kind): PURE (no fs, no `astro:*`; browser-safe), NODE (`node:fs` ok), SERVER (`http`, `run-script`, `markdown`, `ide`: no `astro:*`, server only), SERVER-ASTRO (`entries.ts`: `astro:content`; pages and API only). PURE: `relations`, `frontmatter-patch`, `link-insert`, `reference-yaml`, `schema-comment`, `yaml-doc`, `names`, `reorder`, `json-schema` (scripts/tests only), `forms/*` (incl. `entry-form`). NODE with fs: `entry-index`, `entry-io`, `entry-create`, `atomic-write`, `doc-io`, `reference-io`, `schema-check`; `skill-check` NODE without fs calls. In `src/lib/inflate`: `catalog`, `recipe`, `expand`, `material-plan` (also every type that crosses the inflate API) are PURE (the Inflate island may import only these); `markdown`, `render`, `pipeline` are NODE without fs calls of their own; `fs-sources`, `write`, `output-dir`, `material-exec`, `dir-plan` and `recipe-io.ts` are NODE with fs (`dir-plan` also imports `proc`, so scripts never do); `jobs.ts` and `src/lib/proc.ts` are SERVER. Never import fs/SERVER files from an island; no barrel `index.ts` there. Scripts import only `src/datasets/*` and PURE/NODE libs; tests may add SERVER libs; neither imports `astro:*`. `src/ui/editor` touches `self`/Monaco: import it only from `client:only` islands.
- **Read path (okf + skill)**: lists, summaries, details' frontmatter, the relation graph and invalid-file reporting read FRONTMATTER FROM DISK through `entry-index.ts` (one scan, cached per entry dir by file `(mtimeMs, size)`, 200 ms memo; every write route calls `invalidateEntryIndex()`), so a PATCH, state change or create shows on the very next request and an invalid file is listed with its issues. Collections only provide rendered HTML, the `docs` collection (preview + search index) and references; loaders, watchers and `content.config.ts` are unchanged. Never rebuild lists from `getCollection` for okf/skill.
- **Kit**: use `src/ui/kit` wrappers; raw `ListBoxItem` from react-aria-components is banned outside the kit (oxlint). Kit v2: `Select` (searchable; the SSR native sort select is its CSS twin), `OrderedList` (RAC GridList + drag and drop, grip column only, `keyboardNavigationBehavior="tab"`; callers keep up/down/remove buttons and reorder with `reorderKeys`), `Table` (SSR twin `ck-table`), `Icon` (+ `Icon.astro`), `Disclosure`, `Tabs` with counts. The barrel `kit/index.ts` re-exports `CodeEditor` and so pulls in Monaco; code that must stay Monaco-free (the search island, EntryTools, NewEntryForm, pickers) imports kit parts by file (`../kit/Button.tsx`). `EntryPicker` (`src/ui/pickers`) is the one entry chooser (Insert link, relations, children, Add to context); tag inputs go through `TagEditor`, which splits typed text on commas and whitespace, commits the pending text on blur and keeps invalid tokens in the input.
- **Kit interaction**: `src/ui/kit/Interactive.css` (imported last by `kit.css`) owns `cursor` for every button-like control and the neon-yellow icon-button glow; icon-only buttons use `Button iconOnly` (SSR twin `ck-button--icon`), small text utility buttons (Copy, Esc) `glow` (`ck-button--glow`), a plain `<a>`/`<button>` icon `ck-iconbtn`. Dialogs with a list, an editor or more than three fields use `Modal size="large"` (fixed `min(60rem, 90vw)` x `80vh`, the body or list scrolls inside); confirms and two- or three-field forms stay auto-sized.
- **GridList keys**: RAC grid rows stop key events that start inside a row, so a `window` shortcut listener (Cmd/Ctrl+S) must be registered in the CAPTURE phase (`addEventListener('keydown', fn, true)`) and ignore `defaultPrevented`.
- **Clickable rows**: stretched-link pattern, CSS only (`.cx-rowlink` on the row, ONE `.cx-rowlink__main` anchor whose `::after` covers it); inline buttons, inputs, selects and other links sit above the overlay. No JS row click handlers.
- **CSS**: one entry `src/styles/global.css` (imported by `Base.astro`). No Astro `<style>` blocks (unlayered CSS beats every layer). No CSS imports in `.tsx`. All our rules live in `@layer cx-tokens|cx-base|cx-kit|cx-app|cx-prose|cx-utilities`, declared AFTER cybercore's `reset…utilities`. Astro components use HTML twins of kit classes (`ck-*`); never put `cyber-*` classes on `ck-*` elements or form controls. Dataset colors: `--ds-<id>` in `tokens.css`.
- **Editor**: Monaco is mounted by `CodeEditor` (kit barrel: Forge, Inflate) or `LazyCodeEditor` (`React.lazy` with a same-size `testId` fallback: every other island); both take the same `CodeEditorProps`. Markdown models get link completion registered ONCE in `monaco-setup.ts` (`link-completion.ts` + pure `link-insert.ts`): `ctxman:` (target), `](` (destination), `[[` (whole link) and Ctrl+Space; not a bare `[`. "Insert link to entry…" is Mod+Alt+K (Monaco binds Mod+Shift+K to delete line) plus a context-menu item, opened through `useInsertLink`, which focuses the editor BEFORE the picker mounts so react-aria restores focus into it. A YAML editor of reference/context/recipe passes `schemaDataset`: the model path becomes `file:///data/<ds>/<testId>-<id>.yaml`, which both the schema `fileMatch` and the in-file comment need (`inmemory://` resolves neither); monaco-yaml markers (owner `yaml`) coexist with the `ctxman` markers, and only `YamlIssue`s with `!coveredBySchema` are passed as `markers`. monaco-yaml needs three shims together (remove none): the `createWebWorker` adapter in `monaco-setup.ts`, the Vite alias for `monaco-editor/esm/vs/editor/editor.worker.js` and the `monaco-yaml > …` entries in `optimizeDeps.include`. Schemas are imported statically. An arktype model changes together with `schemas.ts` (parity test), then `pnpm run gen:schemas`.
- **Save model of in-browser editing**: explicit Save only (button or Cmd/Ctrl+S; no autosave). IDE edits keep auto-updating the UI. A successful doc save returns to preview, dims it (`data-stale`) and remembers "Saved" in sessionStorage (`last-save`). Doc saves send `ifUnmodifiedSince`; a 409 opens the ConflictDialog (Keep editing / Load disk version / Overwrite). Validator findings show after a save, never block it.
- **Drafts**: unsaved text of DocEditor, MarkdownModal, Forge and Inflate is mirrored to **localStorage** (`draft-backup.ts`, key prefix `ctxman:draft:`, 14-day TTL, `{text, base, savedAt}`) and restored after any reload with a "Restored unsaved changes" banner (`DraftNotice` / `DraftBanner`; `data-stale` when the file changed on disk since: saving then overwrites it). These islands have NO native `beforeunload` prompt (a dev reload cannot be told from a close); in-app discard/confirm dialogs and the Forge/Inflate `popstate` confirm stay. DataForm and NewEntryForm (no persistence) keep `useUnsavedGuard`.
- **Shared editing layer**: `src/ui/edit/` (SaveBar, ConflictDialog, TagEditor, YamlIssues, `api.ts` `getJson`/`sendJson` that never throw, `draft-backup`, `last-save`, `useUnsavedGuard`, `edit.css`) is browser-only with NO Monaco; import its files and kit parts by file. `src/lib/names.ts` holds `nameProblem` and the tag rule. `ensureEntries`/`ensureAllEntries`/`loadAllEntries`/`waitForEntry` in `src/stores/entries.ts` feed pickers and completion; `parseEditUrl` in `url-state.ts` reads `edit=1` and `view`. `$docEditing` (doc-editor store: a DocEditor is mounted AND in edit mode, not just `?edit=1`, which the reference form uses too) is what locks EntryTools buttons and the state selects (`Leave the editor first`) and holds back its post-write reload.
- **URL is state**: anything that selects data lives in the URL. List: `q`, repeated `state`/`tag`, `sort` (modified|name|state), `type` (reference), `project` (children of a project). Search: `search=1&sq=<query>&in=<ds,ds>` (never `q`). Forge: `context`, `dataset` (a linkable dataset or `all`), `q`, `state`, `tag`. Inflate: `recipe` (slug or `new`), `view` (compose|preview|run), `dataset` (ad hoc tab, or `all`), `q`, `job` (only with `view=run`), `paths` (`absolute`; relative is the default). Tools: `add`. `/new/<ds>`: `parent`. Detail and doc pages: `edit=1` (set with `replaceState`: never a history entry; removed after a save); yaml datasets add `view` (form|yaml). Use `src/lib/url-state.ts`. Not URL state: unsaved edits, action results, ephemeral UI (open dialogs).
- **nanostores pattern**: URL-synced stores read `location` in `onMount`; actions are plain functions that set stores and call `history.pushState/replaceState`; `popstate` re-reads the URL and never writes history; time comes from `$now`, not `Date.now()` in render; `useState` only for local transient drafts.
- **React**: follow the Rules of React (pure render, no setState in effects, no ref reads in render, no mutation). React Compiler is off, but oxlint `react-hooks-js/*` rules enforce compatibility. A prop named `children` is overwritten by Astro's slot children: pass lists as `childEntries`.
- **API**: JSON only via `src/lib/http.ts` (`json`, `apiError`, `readJson`): `cache-control: no-store`, errors `{error, message, issues?}`; mutating routes answer 415 (not JSON), 403 (Origin differs), 400 (bad body), 404, 409 (exists). `PATCH /api/entry/...` edits only the given top-level keys by range-based text splicing (`frontmatter-patch.ts`, every other byte stays), under a per-file lock (`withFileLock`), and NEVER writes frontmatter that fails the dataset schema (400 `invalid`, nothing written; 409 `conflict` when `ifUnmodifiedSince` differs from the file mtime; 422 `invalid-file` when the file's frontmatter is unusable). `PUT /api/doc/...` is the opposite: it always saves, returns validator `warnings` (incl. `links/*`), 409 `conflict` (body carries the CURRENT `lastModified`), 413 above 512 KB, 422 `not-text`, and never creates a file; `POST /api/doc/...` creates a concept (409 `exists`). `POST /api/ide/open` answers 501 `ide-not-found` / 500 `ide-spawn-failed`. `GET /api/schemas/:dataset` answers 404 `unknown-dataset` / 500 `schema-missing`. `/api/inflate/render`, `/write`, `/plan`, `/run` are POST-only and need the same checks; `/write` answers 400 `bad-path` / `write-failed`; `/run` answers 400 `no-dir` / `bad-dir` / `dir-not-directory`, 409 `dir-not-empty` / `manifest-invalid` / `busy`; `/jobs/:id` 400 `bad-id` / 404 `not-found`; `/jobs/:id/cancel` 409 `not-running`. `/api/scripts/:name` runs only `src/lib/scripts-allowlist.ts` entries, answers 200 even when the script exits non-zero, 404 for an unknown name.
- **Cross-platform**: OS-level work uses `node:fs`/`node:path`/`node:util`; spawn `process.execPath` with argv, `shell: false`; no bash/sh scripts. The exceptions: the IDE launcher (`src/lib/ide.ts`) spawns the user's `code` command with `shell: false`, detached (only a win32 `.cmd`/`.bat` goes through `cmd.exe /d /s /c`), and Inflate runs spawn `git`, `tar`, `unzip` through `src/lib/proc.ts` (argv, `shell: false`, never a shell string).
- **Files under the data dir**: every path that comes from a request goes through `safeJoin` / `resolveBundleFile` (`src/lib/bundles.ts`: no `..`, no absolute path, realpath must stay inside the entry dir); writes are atomic (`writeFileAtomic` in `atomic-write.ts`: dot-prefixed temp file in the same dir, then `rename`). The IDE opens only an entry dir (or the data dir for yaml datasets) with a file inside it, never a file alone, and the request never chooses the executable.

## Testing rules

- Unit (`tests/unit`): PURE/NODE/SERVER libs and stores only (no `astro:*`). Build fixtures in OS temp dirs (`tests/unit/fixtures/data-fixtures.ts`); NEVER read or write `./data` (reading the committed `schemas/` is fine); CLIs run with `CTXMAN_DATA_DIR` set. New lib behavior or bugfix = new test.
- E2E (`tests/e2e`): Playwright, 1 worker, data = fresh copy of `./data` in `.tmp/e2e-data` via `CTXMAN_DATA_DIR`, port 4322. Specs rely on seed entry names and counts (`kb/ctxman`, `context/ctxman-dev`, `recipe/ctxman-dev-brief`, `project/ctxman-v1` with 11 children, 4 seed tasks): do not rename or add to seeds without updating specs; `e2e-*` names are reserved for specs (a spec that adds children uses its own `e2e-*` project). `prepare-data.ts` also writes a fake IDE command (`.tmp/e2e-ide/fake-code`) and `playwright.config.ts` points `CTXMAN_IDE_COMMAND` / `CTXMAN_IDE_RECORD` at it; inflate-run specs use a local git repo in `.tmp/e2e-git` via git `insteadOf` (env `GIT_CONFIG_COUNT/KEY_0/VALUE_0`) and `CTXMAN_INFLATE_STEP_DELAY_MS=300`; every run goes into an OS temp dir, NEVER into `~/ctxman-inflate/ctxman-dev-brief`. Writes made outside the browser (API, fs) make the dev server reload connected pages ~0.7 s later: wrap them in `settleAfter(browser, baseURL, writes)` (`tests/e2e/dev-reload.ts`; `settleDevReload()` in `helpers.ts` is the fixed-delay fallback). When running specs by hand pass `--output test-results/<name>` (gitignored; default output collides across runs). Locate by `data-testid` (`grep -rn data-testid src`; registries in `plans/UI_SPEC.md` §L, `plans/ROUND2_UI_SPEC.md` §L, `plans/INFLATE*_SPEC.md`). Islands render only after mount: wait for their test ids (EntryTools: an enabled SSR button or `entry-status`). After an in-browser save wait for the reloaded page. New interactive UI gets a test id.

## Keeping docs current (in the same change as the code)

- Command, dependency, tooling config, directory layout or rule changed: update this file; update the `.oxlintrc.json`/`.oxfmtrc.json` ignore lists (and `.gitignore`) when adding top-level dirs (`schemas/` and `out/` are the latest).
- Dataset, state, field or template changed, in this order: `registry.ts`, `schemas.ts`, `arktypes.ts` (+ `pnpm run gen:schemas`, `fix:yaml-comments` if the comment changed), `content.config.ts`, `templates.ts` + `add-entry.ts`, check libs (`okf`, `links`, `collections-check`), `entry-index`/`entry-io` (okf/skill frontmatter keys), UI (`--ds-*` tokens, kit/search/forge/tools tables, `lib/forms/fields.ts`, `entry-form.ts`), `package.json` `add:<id>`, tests; then docs: `data/kb/ctxman/concepts/datasets.md` + `adding-entries.md` (+ `relations.md` for `links`), `data/skill/ctxman-add-entry/SKILL.md`, the dataset table here.
- Route, URL param or API endpoint: `data/kb/ctxman/concepts/routes-and-api.md` (+ `search.md` / `context-forge.md` / `context-inflate.md` / `editing.md` / `relations.md`) and the lists here. Inflate modes, materials, targets, options, run steps or output format: `context-inflate.md` (it documents `src/lib/inflate/catalog.ts`, `material-plan.ts` and `render.ts`; keep them in step).
- Check rule: `compliance-checks.md`. Run-mode or content-layer behavior: `runtime-modes.md` and Caveats here. Stack or layering: `architecture.md`, Tech and Coding rules here. Editing UI: `editing.md`.
- Editing `data/kb/ctxman`: add a dated line at the top of its `log.md`, list new concepts in `index.md`, then `pnpm run check`. ctxman tracks its own work in its datasets: set the `state` of the matching `task`/`bug`/`feature` (mind the e2e seed counts); record non-obvious root causes with `pnpm run add:rca`.

## Caveats

- `astro dev` sends a full browser reload ~0.7s after a change under `data/` that a glob loader sees (not `context/*.yaml` or `recipe/*.yaml`); the first browser connection after start gets one reload too. Tools output survives via `sessionStorage`.
- **Dev reload after an in-browser write**: saving through `PUT /api/doc/...`, `PATCH /api/entry/...`, `POST /api/entry/...`, `POST /api/doc/...` (okf `.md`, `SKILL.md`) or writing a reference triggers that reload ~0.7s later. Lists, summaries and frontmatter are read from disk (see Read path), and a page renders the DISK body whenever the content layer's copy differs (it re-reads a written file ~1s late; `htmlFor` in `entries.ts`), so the reloaded page is current. `src/stores/doc-editor.ts` still schedules exactly ONE more `location.reload()` 1.5s after the first post-save reload as a safeguard (the sessionStorage "Saved" record carries a `reloads` counter; no loop). The state select (`shell.ts`) and EntryTools rely on the dev reload and only run a fallback reload in a production build (`pnpm start` has no watcher). Context/recipe saves have no dev reload; their popups and forms navigate or reload themselves. `GET /api/doc` and `GET /api/reference/:slug` always read the disk. A built server keeps its collection snapshot.
- A saved file with unparsable frontmatter is allowed on purpose for the doc editor (warnings only): the running dev server logs a glob-loader error, and a fresh `astro dev` / `astro sync` fails until it is fixed (`pnpm run check:okf` names the file). The frontmatter PATCH can never cause that. The dev log line `Entry docs → … was not found` right after creating a concept is harmless (the doc page falls back to the disk until the content layer catches up).
- **Open in IDE**: the command is `CTXMAN_IDE_COMMAND` (a name looked up in PATH, or a path; set but missing = 501, no fallback), else `code` in PATH, else the usual VS Code install locations (win32: PATHEXT, `code.cmd`). It is run as `<command> <entry dir> <file>` without flags; `{ dir }` (a directory with a readable `.ctxman-inflate.json`) runs `<command> <dir>`. The Windows `.cmd` path is untested on a real Windows host.
- Stuck or looping dev reloads, "new dependency" errors: stop the server and `rm -rf node_modules/.vite/deps`.
- Freshness is fs mtime, so `git checkout`/clone resets "modified" times.
- `astro build` snapshots collections; runtime reads (entry index, contexts, recipes, freshness, search index, Inflate) go to the filesystem.
- **Inflate**: the document is generated on request from the files on disk (a built server stays current). Paths in it are absolute and machine specific. Only an `eager` pointer uses a bare `@path`; every other path is backticked so nothing is force-loaded. Brief quality: every okf kind defaults to `inline-main`; an inline okf item also prints its `description` when the body lacks it; empty template headings are dropped (`dropEmptySections`); markdown blocks nest under their group and are titled by their first heading; a link that does not resolve adds an `unresolved-link` warning. `shiftHeadings` handles ATX headings only. `/api/inflate/write` takes an absolute `.md` path outside `node_modules`, `.git` and the data dir (home is NOT required); the UI default is `out/<recipe>.md`. Clones and downloads in the generated commands use `.ctxman/` inside the target project. Output over 512 KB adds a `large-output` warning. Stale overrides and order keys are only warnings until "Prune stale" removes them; removing a context, item or block in the UI prunes automatically.
- **Inflate into a directory** (`output.dir`, or the run-override `dir`; absolute or `~/…`): `POST /api/inflate/plan` (dry run) -> `/run` (202 job, ONE run at a time, 409 `busy`) -> the UI polls `GET /api/inflate/jobs/:id` every 500 ms. Jobs live in memory (last 20, lost on a server restart; `view=run&job=<id>` resumes after a reload). Per item a `material` is placed (okf symlink|copy at `<ds>/<slug>`, skill copy at `<skillsDir>/<name>`, local-repo symlink / remote-repo clone at `repos/<slug>`, remote-skill install, or `none`); `output.primary` is one such repo. Run overrides go through the pure `applyRunOverrides` BEFORE expansion. A run writes `LLM_CONTEXT.md`, stubs (`CLAUDE.md` = `@LLM_CONTEXT.md` for claude-code, `AGENTS.md` for codex/generic, `.gitignore`; only when absent or unedited) and `.ctxman-inflate.json`, the record of what ctxman owns there.
- **Inflate directory safety**: `dir` must be outside the repo and the data dir (and not contain them), not a filesystem root or `$HOME`, no `node_modules`/`.git` segment; a non-empty dir needs a ctxman manifest or `allowNonEmpty`. A re-run deletes or replaces ONLY paths in the previous manifest that are still what ctxman created: clones with local or unpushed changes, edited stubs and retyped paths are kept and reported; symlinks are unlinked, never followed; every step path goes through `safeJoin` plus a realpath check. `git`, `tar` (bsdtar; `unzip` fallback) are system tools: a missing one demotes only the items needing it to `none` with a `tool-missing` warning. Git runs with `GIT_TERMINAL_PROMPT=0` and ssh BatchMode. Directory links are junctions on Windows, which is untested.
