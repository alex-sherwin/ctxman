# AGENTS.md

ctxman (context manager): a local-only Astro SSR app (Node backend, never deployed) that keeps knowledge, work items, skills and external references as files under `data/`, and assembles them into reusable **contexts** (evergreen link sets) for agentic coding sessions. **Context Inflate** (`/inflate`, dataset `recipe`) expands contexts plus extra items into one markdown document and manifest for Claude Code, Codex or a generic agent; design in `data/kb/ctxman/concepts/context-inflate.md`. In-browser editing (markdown docs, popups, forms, Open in IDE) is described in `data/kb/ctxman/concepts/editing.md`.

**pnpm only** (never npm/npx/yarn; no `package-lock.json`). Node >= 24. Run the app with `pnpm run dev` (http://127.0.0.1:4321).

Routes: `/` dashboard, `/<ds>` list (`/recipe` too), `/<ds>/<slug>` detail, `/<ds>/<slug>/doc/<path>` (okf only, no `.md`), `/new/<ds>` (create form; reference, context, recipe only, 404 otherwise: use `/tools` for the rest), `/forge` (build contexts), `/inflate` (compose recipes, generate the agent document), `/tools` (run allowlisted scripts; a created entry opens automatically), `/search` (302 to `/?search=1&sq=&in=`), 404. Edit mode is the same URL plus `?edit=1`: okf and skill detail/doc pages switch Preview to a Monaco source editor (DocEditor, details column left, preview right, "Open in IDE" button); reference, context and recipe detail pages swap the main column for the DataForm (`view=form|yaml` picks its tab). Context and recipe detail pages also have pencil buttons that open small markdown popups (link notes, preamble, blocks). List and dashboard rows are whole-row links. Global search modal on every page (Cmd/Ctrl+K). API (`src/pages/api`): `GET /api/search-index.json`, `GET /api/entries?dataset=`, `GET|PUT|DELETE /api/context/:slug`, `POST /api/context`, `GET|PUT|DELETE /api/recipe/:slug`, `POST /api/recipe`, `GET|PUT|DELETE /api/reference/:slug`, `POST /api/reference`, `GET|PUT /api/doc/<dataset>/<slug>/<...path>` (read / save one existing `.md` of an okf bundle or skill; `{ markdown, ifUnmodifiedSince? }`), `GET|POST /api/ide/open` (POST `{ dataset, slug, path? }` opens the entry folder plus file in the IDE; GET reports availability), `GET /api/schemas/:dataset` (the committed JSON Schema of reference|context|recipe), `POST /api/inflate/render` (recipe body -> `{ markdown, manifest }`), `POST /api/inflate/write` (`{ recipe, path }`), `POST /api/scripts/:name`.

## Datasets (11; `name` == dir/file stem == slug == collection id; `^[a-z0-9]+(-[a-z0-9]+)*$`, max 64)

| id                     | kind               | entry file (under `data/`) | `state` (kebab-case; first = default)                                                                             |
| ---------------------- | ------------------ | -------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| kb, rca                | okf bundle         | `<id>/<name>/main.md`      | none                                                                                                              |
| idea                   | okf bundle         | `idea/<name>/main.md`      | pending, in-progress, complete, abandoned                                                                         |
| task, feature, project | okf bundle         | `<id>/<name>/main.md`      | pending, in-progress, complete, wont-do                                                                           |
| bug                    | okf bundle         | `bug/<name>/main.md`       | pending, in-progress, fixed, wont-fix                                                                             |
| skill                  | agentskills.io dir | `skill/<name>/SKILL.md`    | none                                                                                                              |
| reference              | yaml               | `reference/<name>.yaml`    | none; `type` local-repo / remote-repo / remote-skill (uri: git, or https archive for skills), `owner` me / not-me |
| context                | yaml               | `context/<name>.yaml`      | none; `links: [{dataset, slug, notes?}]`                                                                          |
| recipe                 | yaml               | `recipe/<name>.yaml`       | none; contexts, items, overrides, order, markdown, preamble (+ `target`, `layout`, `defaults`)                    |

- **OKF v0.2** (okf datasets): root `index.md` frontmatter is ONLY `okf_version: "0.2"`; nested `index.md` and `log.md` have no frontmatter; `main.md` needs `type` (registry `okfType`), `name`, `description`, plus `state` for lifecycle datasets; every other `*.md` concept needs a non-empty `type`; `log.md` = `## YYYY-MM-DD` headings newest first; `stale_after` = `YYYY-MM-DD`; unknown keys are kept.
- **Links**: inside a bundle `/x.md` (bundle root) or `./x.md` must resolve to an existing file; across entries ONLY `ctxman:<dataset>/<slug>` (a `/feature/x` path would be read as a bundle path). Missing `ctxman:` targets are warnings.
- **reference** `uri` (rules in `src/lib/remote-uri.ts`, never `z.url()`): `remote-repo` = git URI (`git@host:org/repo.git`, `ssh://git@host/org/repo.git`, `https://host/org/repo[.git]`); `remote-skill` = git URI OR `https://…(.tar.gz|.tgz|.zip)` archive, shown with a derived `git`/`archive` badge. Read/written through `src/lib/reference-io.ts` at runtime (CRUD API + DataForm) but keeps its glob loader WITH watcher (SSR lists lag a write by ~0.6 s).
- **skill** frontmatter is strict: `name` (== dir), `description`, optional `license`, `compatibility`, `metadata`, `allowed-tools`.
- **context** = pointers, never vendored content; no duplicate links, no link to `context` or `recipe`, `name` immutable. Always read/written through `src/lib/context-io.ts` (atomic write), NEVER `getCollection('context')`.
- **recipe** = a saved Context Inflate composition (`target` claude-code|codex|generic, `layout` grouped|flat, `contexts`, ad hoc `items`, `markdown` blocks, `overrides`, `order`, per-kind `defaults`, `preamble`); strict schema, `name` immutable, NOT linkable (`LINKABLE_DATASETS` excludes it). Always read/written through `src/lib/recipe-io.ts` (atomic write, key order fixed by `serializeRecipe`), NEVER `getCollection('recipe')`. Four check warnings: `collections/recipe-context-missing`, `recipe-item-missing`, `recipe-override-stale`, `recipe-order-stale` (the last two only when every listed context exists and is valid).
- **YAML data files** (reference, context, recipe) start with line 1 `# yaml-language-server: $schema=../../schemas/<ds>.schema.json` (IDE and Monaco feedback). The io writers and `templates.ts` add it through `withSchemaComment` (`src/lib/schema-comment.ts`); the serializers never do. Missing/wrong = warning `collections/yaml-schema-comment`; `pnpm run fix:yaml-comments` repairs. The relative path only resolves for the default `./data`.
- Freshness = fs mtime (max over the entry dir) computed per request; `stale_after` reached = stale.
- Create entries with the scripts or the `/new/<ds>` forms (never copy folders); finish with `pnpm run check` at 0 errors / 0 warnings.

## Tech (binding; the why is in italics)

- **Runtime**: Node 24 runs `.ts` directly, never transpile (scripts, e2e helpers). _Type stripping: erasable syntax only._ pnpm 11 (`packageManager`).
- **TypeScript**: `typescript@next` 7.1 nightly (native `tsc`). _`@astrojs/ts-content-mapper` (tsconfig `contentMappers`) makes the same `tsc` check `.astro` files, so `astro check` is NOT used and `@astrojs/check` must not be installed._ `noUncheckedIndexedAccess` stays off (Astro's own components fail under it).
- **Framework**: Astro 7.4.0, `output: 'server'`, `@astrojs/node` standalone, content collections for every dataset. Markdown via Satteri (`@astrojs/markdown-satteri`); never add `@astrojs/markdown-remark`.
- **UI**: React 19 islands (exactly 7, all `client:only="react"`): SearchWidget in `Base.astro` (every page), Forge (`/forge`), Inflate (`/inflate`), ToolsRunner (`/tools`), DocEditor (okf + skill detail and sub-doc pages), MarkdownTargets (`/context/<slug>`, `/recipe/<slug>`), DataForm (`/<ds>/<slug>?edit=1` and `/new/<ds>` for reference/context/recipe) + react-aria-components kit + vanilla CSS. Everything else is SSR Astro. The three newer islands load Monaco lazily.
- **Theme**: `cybercore-css` 0.3 (dark only) as base layer; Inter Variable + Hack self-hosted from npm (no CDN, no Google Fonts). Information-dense layout.
- **Editing**: Monaco (`monaco-editor` + `@monaco-editor/react`, loaded locally via Vite workers) for EVERY multi-line markdown/JSON/YAML input; plain `TextField` for single-line values. `monaco-yaml` 5.5.1 gives YAML editors diagnostics, hover and completion from `schemas/*.schema.json` (see Coding rules, Editor).
- **State**: nanostores + `@nanostores/react`; the URL carries all page state.
- **Other**: zod 4 imported from `zod`, not `astro:content` (_so Node scripts share the schemas_; zod is the only runtime validator); `arktype` 2.2.8 (devDependency: models in `src/datasets/arktypes.ts` exist only to generate `schemas/*.json`, never imported by pages, API routes or islands); fuse.js 7 search; `yaml`; oxlint + oxfmt (`.oxlintrc.json`, `.oxfmtrc.json`); vitest 5; Playwright 1.64.
- New dependency: `pnpm add`, record it here. Add new client deps to `vite.optimizeDeps.include` in `astro.config.ts` (prevents mid-session dev reloads).

## Coding rules

- **TypeScript only.** Erasable syntax: no `enum`, `namespace` with values, constructor parameter properties, `import x = require`; use `as const` + unions. Relative imports carry the extension (`./x.ts`, `./X.tsx`); `import type` for types; `.ts`/`.tsx` never import `.astro`. Import CSS packages from CSS, not TS (TS 7 side-effect import check).
- **Layering of `src/lib`** (each file's header comment names its kind): PURE (no fs, no `astro:*`; browser-safe), NODE (`node:fs` ok), SERVER (`http`, `run-script`, `markdown`, `ide`: no `astro:*`, server only; `ide.ts` spawns `node:child_process`), SERVER-ASTRO (`entries.ts`: `astro:content`; pages and API only). In `src/lib/inflate`: `catalog`, `recipe`, `expand` are PURE (the Inflate island may import only these); `markdown`, `render`, `pipeline` are NODE without fs calls of their own (they import `okf.ts`/`links.ts`); `fs-sources`, `write` and `recipe-io.ts` are NODE with fs. Round 2: `reference-yaml`, `schema-comment`, `yaml-doc`, `names`, `reorder`, `forms/*` are PURE (islands may import them); `doc-io`, `reference-io`, `schema-check` are NODE with fs, `skill-check` NODE without fs calls; `json-schema.ts` (PURE) and `src/datasets/arktypes.ts` are for scripts and tests only. Never import fs/SERVER files from an island; no barrel `index.ts` there. Scripts import only `src/datasets/*` and PURE/NODE libs; tests may add SERVER libs; neither imports `astro:*`. `src/ui/editor` touches `self`/Monaco: import it only from `client:only` islands.
- **Kit**: use `src/ui/kit` wrappers; raw `ListBoxItem` from react-aria-components is banned outside the kit (oxlint). Kit v2: `Select` (RAC Select + Autocomplete in the popover: searchable, chevron flips; the SSR native sort select is its CSS twin), `OrderedList` (RAC GridList + drag and drop, mouse drags start only in the grip column, `keyboardNavigationBehavior="tab"`; callers keep up/down/remove buttons as fallback and reorder with `reorderKeys` from `src/lib/reorder.ts`), `Table` (RAC Table; SSR twin `ck-table`), `Icon` (+ `src/components/Icon.astro`), `Disclosure` (chevron, optional one-line `preview` while closed), `Tabs` with counts. The barrel `kit/index.ts` re-exports `CodeEditor` and so pulls in Monaco; code that must stay Monaco-free (the search island, on every page, and the lazy-Monaco islands) imports kit parts by file (`../kit/Button.tsx`).
- **GridList keys**: RAC grid rows (OrderedList in Forge and Inflate) stop key events that start inside a row, so a `window` shortcut listener (Cmd/Ctrl+S) must be registered in the CAPTURE phase (`addEventListener('keydown', fn, true)`) and ignore `defaultPrevented` (a Monaco save action already handled it).
- **Clickable rows**: stretched-link pattern, CSS only (`.cx-rowlink` on the row, ONE `.cx-rowlink__main` anchor whose `::after` covers it, `app.css`); inline buttons, inputs and other links sit above the overlay, ctrl/cmd-click still opens a tab. No JS row click handlers.
- **CSS**: one entry `src/styles/global.css` (imported by `Base.astro`). No Astro `<style>` blocks (unlayered CSS beats every layer). No CSS imports in `.tsx`. All our rules live in `@layer cx-tokens|cx-base|cx-kit|cx-app|cx-prose|cx-utilities`, declared AFTER cybercore's `reset…utilities`. Astro components use HTML twins of kit classes (`ck-*`); never put `cyber-*` classes on `ck-*` elements or form controls. Dataset colors: `--ds-<id>` in `tokens.css`.
- **Editor**: Monaco is mounted by `CodeEditor` (static import through the kit barrel: Forge, Inflate) or `LazyCodeEditor` (`src/ui/editor/LazyCodeEditor.tsx`, `React.lazy` with a same-size `testId` fallback: every other island, so a page does not fetch the ~4 MB editor until it renders one); both take the same `CodeEditorProps`. A YAML editor of reference/context/recipe passes `schemaDataset`: the model path becomes `file:///data/<ds>/<testId>-<id>.yaml`, which is what BOTH the schema `fileMatch` and the in-file `# yaml-language-server: $schema=../../schemas/<ds>.schema.json` comment need (`inmemory://` URIs resolve neither). monaco-yaml markers (owner `yaml`) coexist with the `ctxman` markers; an editor with `schemaDataset` passes only the `YamlIssue`s with `!coveredBySchema` (`src/lib/yaml-doc.ts`; JSON Schema cannot express duplicate links or a changed `name`) as `markers`, so nothing shows twice, and the zod check still gates Save. monaco-yaml needs three shims together (remove none): the `createWebWorker` adapter in `monaco-setup.ts` (monaco-worker-manager still calls the pre-0.5x API), the Vite alias for `monaco-editor/esm/vs/editor/editor.worker.js` and the `monaco-yaml > …` entries in `optimizeDeps.include` (`astro.config.ts`), else the YAML worker dies or dev reloads mid-session. The schemas are imported statically (not fetched; `/api/schemas` is for external tools). An arktype model changes together with `schemas.ts` (a parity test enforces it), then `pnpm run gen:schemas`.
- **Save model of in-browser editing**: explicit Save only (button or Cmd/Ctrl+S; no autosave, no debounce). IDE edits keep auto-updating the UI (glob loaders and the dev reload are unchanged), so every editor tolerates the dev full reload that follows its own save: a successful save returns to preview, dims it (`data-stale`) and remembers "Saved" in sessionStorage (`last-save`); unsaved text is mirrored there too (`draft-backup`) and restored after a reload. Doc saves send `ifUnmodifiedSince`; a 409 opens the ConflictDialog (Keep editing / Load disk version / Overwrite). Findings from the validators are shown after a save, never block it.
- **Shared editing layer**: `src/ui/edit/` (SaveBar, ConflictDialog, TagEditor, YamlIssues, `api.ts` `getJson`/`sendJson` that never throw, `draft-backup`, `last-save`, `useUnsavedGuard`, `edit.css`) is browser-only with NO Monaco; import its files and kit parts by file. `src/lib/names.ts` (PURE) holds `nameProblem` and the tag rule (`src/ui/forge/validate-name.ts` re-exports it). `waitForEntry(ds, slug)` in `src/stores/entries.ts` polls `GET /api/entries` until a just-created entry is listed (okf, skill and reference entries appear ~0.6 s after the write); `parseEditUrl` in `url-state.ts` reads `edit=1` and `view=form|yaml`.
- **URL is state**: anything that selects data lives in the URL. List: `q`, repeated `state`/`tag`, `sort` (modified|name|state), `type` (reference). Search: `search=1&sq=<query>&in=<ds,ds>` (never `q`). Forge: `context`, `dataset`, `q`, `state`, `tag`. Inflate: `recipe` (slug or `new`), `view` (compose|preview), `dataset` (ad hoc tab), `q`. Tools: `add`. Detail and doc pages: `edit=1` (edit mode, set with `replaceState`: never a history entry; removed again after a save); yaml datasets add `view` (form|yaml). Use `src/lib/url-state.ts`. Not URL state: unsaved edits, action results, ephemeral UI.
- **nanostores pattern**: URL-synced stores read `location` in `onMount`; actions are plain functions that set stores and call `history.pushState/replaceState`; `popstate` re-reads the URL and never writes history; time comes from `$now`, not `Date.now()` in render; `useState` only for local transient drafts.
- **React**: follow the Rules of React (pure render, no setState in effects, no ref reads in render, no mutation). React Compiler is off, but oxlint `react-hooks-js/*` rules enforce compatibility.
- **API**: JSON only via `src/lib/http.ts` (`json`, `apiError`, `readJson`): `cache-control: no-store`, errors `{error, message, issues?}`; mutating routes answer 415 (not JSON), 403 (Origin differs), 400 (bad body), 404, 409 (exists). `PUT /api/doc/...` always saves and returns validator `warnings` (never blocks), 409 `conflict` (body carries the CURRENT `lastModified`) when `ifUnmodifiedSince` differs from the file's mtime, 413 above 512 KB, 422 `not-text`, and never creates a file. `POST /api/ide/open` answers 501 `ide-not-found` / 500 `ide-spawn-failed`. `GET /api/schemas/:dataset` answers 404 `unknown-dataset` / 500 `schema-missing`. `/api/inflate/render` and `/write` are POST-only and need the same checks; `/write` answers 400 `bad-path` / `write-failed`. `/api/scripts/:name` runs only `src/lib/scripts-allowlist.ts` entries, answers 200 even when the script exits non-zero, 404 for an unknown name; an add run reports `created: { dataset, slug, path, url }`.
- **Cross-platform**: OS-level work uses `node:fs`/`node:path`/`node:util`; spawn `process.execPath` with argv, `shell: false`; no bash/sh scripts. The one exception is the IDE launcher (`src/lib/ide.ts`): it spawns the user's `code` command with `shell: false`, detached; only a win32 `.cmd`/`.bat` goes through `cmd.exe /d /s /c`.
- **Files under the data dir**: every path that comes from a request goes through `safeJoin` / `resolveBundleFile` (`src/lib/bundles.ts`: no `..`, no absolute path, realpath must stay inside the entry dir); writes are atomic (temp file in the same dir, then `rename`; doc temp files are dot-prefixed so globs ignore them). The IDE opens only an entry dir (or the data dir for yaml datasets) with a file inside it, never a file alone, and the request never chooses the executable.

## Testing rules

- Unit (`tests/unit`): PURE/NODE/SERVER libs and stores only (no `astro:*`). Build fixtures in OS temp dirs (`tests/unit/fixtures/data-fixtures.ts`); NEVER read or write `./data` (reading the committed `schemas/` is fine); CLIs run with `CTXMAN_DATA_DIR` set. New lib behavior or bugfix = new test.
- E2E (`tests/e2e`): Playwright, 1 worker, data = fresh copy of `./data` in `.tmp/e2e-data` via `CTXMAN_DATA_DIR`, port 4322. Specs rely on seed entry names (e.g. `kb/ctxman`, `context/ctxman-dev`, `recipe/ctxman-dev-brief`): do not rename seeds without updating specs; `e2e-*` names are reserved for specs. `prepare-data.ts` also writes a fake IDE command (`tests/e2e/fixtures/fake-code.mjs` -> `.tmp/e2e-ide/fake-code`) and `playwright.config.ts` points `CTXMAN_IDE_COMMAND` / `CTXMAN_IDE_RECORD` at it, so no spec ever starts a real editor. Locate by `data-testid` (registry: `plans/UI_SPEC.md` §L and `plans/ROUND2_UI_SPEC.md` §L, Inflate ids in `plans/INFLATE_SPEC.md` §11.3; `grep -rn data-testid src`). Islands render only after mount: wait for their test ids. After an in-browser save wait for the reloaded page (the doc spec's `expectPreviewShows`). New interactive UI gets a test id.

## Keeping docs current (in the same change as the code)

- Command, dependency, tooling config, directory layout or rule changed: update this file; update the `.oxlintrc.json`/`.oxfmtrc.json` ignore lists (and `.gitignore`) when adding top-level dirs (`schemas/` and `out/` are the latest).
- Dataset, state, field or template changed, in this order: `registry.ts`, `schemas.ts`, `arktypes.ts` (+ `pnpm run gen:schemas`, `fix:yaml-comments` if the comment changed), `content.config.ts`, `templates.ts` + `add-entry.ts`, check libs (`okf`, `links`, `collections-check`), UI (`--ds-*` tokens, kit/search/forge/tools tables, `lib/forms/fields.ts`), `package.json` `add:<id>`, tests; then docs: `data/kb/ctxman/concepts/datasets.md` + `adding-entries.md`, `data/skill/ctxman-add-entry/SKILL.md`, the dataset table here.
- Route, URL param or API endpoint: `data/kb/ctxman/concepts/routes-and-api.md` (+ `search.md` / `context-forge.md` / `context-inflate.md` / `editing.md`) and the lists here. Inflate modes, targets, options or output format: `context-inflate.md` (it documents `src/lib/inflate/catalog.ts` and `render.ts`; keep them in step).
- Check rule: `compliance-checks.md`. Run-mode or content-layer behavior: `runtime-modes.md` and Caveats here. Stack or layering: `architecture.md`, Tech and Coding rules here. Editing UI: `editing.md`.
- Editing `data/kb/ctxman`: add a dated line at the top of its `log.md`, list new concepts in `index.md`, then `pnpm run check`. ctxman tracks its own work in its datasets: set the `state` of the matching `task`/`bug`/`feature`; record non-obvious root causes with `pnpm run add:rca`.

## Caveats

- `astro dev` sends a full browser reload ~0.7s after a change under `data/` that a glob loader sees (not `context/*.yaml` or `recipe/*.yaml`); the first browser connection after start gets one reload too. Tools output survives via `sessionStorage`.
- **Dev reload after an in-browser save**: saving through `PUT /api/doc/...` (okf `.md`, `SKILL.md`; not another file in a skill dir) or writing a reference triggers that reload ~0.7s later, but Astro's content layer re-reads the file only after ~1s, so the reloaded page can still render the OLD markdown. `src/stores/doc-editor.ts` therefore schedules exactly ONE more `location.reload()` 1.5s after the first post-save reload (the sessionStorage "Saved" record carries a `reloads` counter, so "Saved" stays visible and it never loops; `pnpm start` has no watcher: the 2s fallback reload plus that one). Context/recipe saves have no dev reload; their popups and the DataForm navigate or reload themselves. SSR pages and `/api/entries?dataset=reference` lag ~0.6s behind a reference write; `GET /api/doc` and `GET /api/reference/:slug` always read the disk. A built server keeps its snapshot.
- A saved file with unparsable frontmatter is allowed on purpose (warnings only): the running dev server logs a glob-loader error, and a fresh `astro dev` / `astro sync` fails until it is fixed (`pnpm run check:okf` names the file).
- **Open in IDE**: the command is `CTXMAN_IDE_COMMAND` (a name looked up in PATH, or a path; set but missing = 501, no fallback), else `code` in PATH, else the usual VS Code install locations (win32: PATHEXT, `code.cmd`). It is run as `<command> <entry dir> <file>` without flags (a file alone would open in the last active window; `-r` would replace its folder). The Windows `.cmd` path is untested on a real Windows host.
- Stuck or looping dev reloads, "new dependency" errors: stop the server and `rm -rf node_modules/.vite/deps`.
- Freshness is fs mtime, so `git checkout`/clone resets "modified" times.
- `astro build` snapshots collections; runtime reads (contexts, recipes, freshness, search index, Inflate) go to the filesystem.
- **Inflate**: the document is generated on request from the files on disk (a built server stays current). Paths in it are absolute and machine specific. Only an `eager` pointer uses a bare `@path` (Claude Code loads the file); every other path is backticked so nothing is force-loaded. `shiftHeadings` handles ATX headings only (setext headings stay as written). `/api/inflate/write` takes an absolute `.md` path outside `node_modules`, `.git` and the data dir (home is NOT required; e2e writes under the OS temp dir); the UI default is `out/<recipe>.md`. Clones and downloads in the generated commands use `.ctxman/` inside the target project. Output over 512 KB adds a `large-output` warning; use `summary`/`pointer` modes. Stale overrides and order keys are only warnings (check rules and the Composition pane) until "Prune stale" removes them; removing a context, item or block in the UI prunes automatically.
