# AGENTS.md

ctxman (context manager): a local-only Astro SSR app (Node backend, never deployed) that keeps knowledge, work items, skills and external references as files in a **data directory** (`CTXMAN_DATA_DIR`, required; the committed sample corpus is `tests/data/`), links them with typed **relations**, and assembles them into reusable **contexts** (evergreen link sets) for agentic coding sessions. **Context Inflate** (`/inflate`, dataset `recipe`) expands contexts plus extra items into one markdown document and manifest, OR (v2) into a **working directory** (symlinked / copied / cloned / installed material plus `LLM_CONTEXT.md`) for Claude Code, Codex or a generic agent; design in `tests/data/kb/ctxman/concepts/context-inflate.md`. An embedded **MCP server** (`POST /mcp`) exposes the same data to agents. In-browser editing is in `concepts/editing.md`, relations in `concepts/relations.md`, MCP in `concepts/mcp.md` (same folder).

**pnpm only** (never npm/npx/yarn; no `package-lock.json`). Node >= 24. Run the app with `pnpm run dev` (http://127.0.0.1:4321) after setting `CTXMAN_DATA_DIR` (shell variable or a `.env` file at the repo root, see `.env.example`; to try the sample corpus use `CTXMAN_DATA_DIR=tests/data`, but that edits the committed files).

There are NO Astro content collections (`src/content.config.ts` is gone): every dataset is read from disk per request.

Routes: `/` dashboard, `/<ds>` list (`/recipe` too; `?project=<slug>` = the children of that project), `/<ds>/<slug>` detail, `/<ds>/<slug>/doc/<path>` (okf only, no `.md`; a `….md` URL 301s to it; `doc/index` (the entry) 301s to the detail page; a missing concept path of an existing bundle offers "Create this file"), `/new/<ds>` (create form for ALL 11 datasets; `?parent=<project>` prefills "Part of project"), `/forge` (build contexts), `/inflate` (compose recipes, generate the document, or run it into a working directory: `view=run`), `/tools` (run allowlisted scripts; its Add Entry panel links to `/new/<ds>`), `/search` (302 to `/?search=1&sq=&in=`), `/mcp` (the MCP endpoint, below), 404. Context and recipe pages have pencil buttons for markdown popups. Rows are whole-row links. Global search modal on every page (Cmd/Ctrl+K).

API (`src/pages/api`): `GET /api/search-index.json`; `GET /api/entries?dataset=`; `GET|PUT|DELETE /api/context/:slug`, `POST /api/context`, `POST /api/context/:slug/links` (append `{links}`, answers `added`/`skipped`); `GET|PUT|DELETE /api/recipe/:slug`, `POST /api/recipe`; `GET|PUT|DELETE /api/reference/:slug`, `POST /api/reference`; `GET|PATCH /api/entry/:ds/:slug` (okf + skill frontmatter: `state title description tags stale_after status links addLinks removeLinks ifUnmodifiedSince`); `POST /api/entry/:ds` (create, `{name, description, title?, state?, tags?, parent?}`, `parent` = a project that gets the child link); `GET|PUT|POST /api/doc/<ds>/<slug>/<...path>` (read / save one existing `.md` / create a concept: also adds the line under `## Concepts` of the entry `index.md` and the `log.md` entry; the reserved names are the root `index.md` (the entry), nested `index.md` and `log.md`); `GET|POST /api/ide/open`; `GET /api/schemas/:dataset` (also `:dataset.schema.json`; CORS `*`: the YAML modelines point here); `POST /api/inflate/{render,write,plan,run}`, `GET /api/inflate/jobs/:id`, `POST /api/inflate/jobs/:id/cancel`; `POST /api/scripts/:name`; `POST /mcp` (MCP Streamable HTTP, stateless; `GET`/`DELETE` answer 405).

## Data directory and environment

- `CTXMAN_DATA_DIR` is **required everywhere** (server, scripts, tests): the directory that holds `kb/ task/ reference/ context/ …`. There is no default. Relative values resolve against `process.cwd()`. `src/lib/data-dir.ts` (`resolveDataDir()` throws `DataDirError` `unset|missing|not-directory`; `dataDirStatus()`; `resolveServerOrigin()`) is the only reader; call it inside functions, never at module top level.
- `.env` at the repo root is honoured because the `dev`, `start`, `preview`, `add:*`, `check`, `check:data|okf|links|collections`, `fix:yaml-comments` and `migrate:index` scripts run `node --env-file-if-exists=.env`. `gen:schemas`, `check:schemas`, `build`, `typecheck`, lint, fmt and tests need no data dir.
- `CTXMAN_SERVER_ORIGIN` (optional, default `http://127.0.0.1:4321`) is the origin written into YAML modelines.
- Unset or unusable: scripts print the message and exit 2; the server answers 503 from `src/middleware.ts` (JSON `{error:'data-dir', message}` for `/api/*` and `/mcp*`, a self-contained HTML instructions page elsewhere) and re-checks every 2 s, so fixing the variable needs a restart (env is read at startup) but a created directory is picked up live.

## Datasets (11; `name` == dir/file stem == slug; `^[a-z0-9]+(-[a-z0-9]+)*$`, max 64)

| id                     | kind               | entry file (under the data dir) | `state` (kebab-case; first = default)                                                                             |
| ---------------------- | ------------------ | ------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| kb, rca                | okf bundle         | `<id>/<name>/index.md`          | none                                                                                                              |
| idea                   | okf bundle         | `idea/<name>/index.md`          | pending, in-progress, complete, abandoned                                                                         |
| task, feature, project | okf bundle         | `<id>/<name>/index.md`          | pending, in-progress, complete, wont-do                                                                           |
| bug                    | okf bundle         | `bug/<name>/index.md`           | pending, in-progress, fixed, wont-fix                                                                             |
| skill                  | agentskills.io dir | `skill/<name>/SKILL.md`         | none                                                                                                              |
| reference              | yaml               | `reference/<name>.yaml`         | none; `type` local-repo / remote-repo / remote-skill (uri: git, or https archive for skills), `owner` me / not-me |
| context                | yaml               | `context/<name>.yaml`           | none; `links: [{dataset, slug, notes?}]`                                                                          |
| recipe                 | yaml               | `recipe/<name>.yaml`            | none; contexts, items, overrides, order, markdown, preamble (+ `target`, `layout`, `defaults`, `output`)          |

- **OKF v0.2** (okf datasets): a bundle is `<ds>/<name>/index.md` (REQUIRED, the entry) + optional `log.md` + concept files. The root `index.md` is both the entry and the bundle navigation: frontmatter `okf_version: "0.2"` FIRST, then `type` (registry `okfType`), `name`, `description`, `state` for lifecycle datasets, `tags`, `links`, `stale_after`, provenance; its body is the entry content and may end with a `## Concepts` navigation section that `addConceptToIndex` keeps maintaining (it appends the section when absent). Nested `index.md` and `log.md` have no frontmatter; every other `*.md` concept needs a non-empty `type`; `log.md` = `## YYYY-MM-DD` headings newest first; `stale_after` = `YYYY-MM-DD`; unknown keys are kept. There is NO `main.md` anywhere (it was folded into `index.md` in Phase 7; `pnpm run migrate:index` converts an older data dir and is idempotent). This deviates from the OKF v0.2 reference skill, which keeps the root `index.md` free of concept semantics (documented in `kb/okf-format`). Check rules: `okf/missing-index` (error: no entry), `okf/index-frontmatter` (error: `okf_version` present and not `"0.2"`), `okf/index-version` (warning: absent). Inflate mode ids such as `inline-main` are stored in recipes and the recipe JSON Schema, so the ids stayed; only their labels say "entry".
- **Relations**: an okf entry `index.md` may carry `links: [{dataset, slug, rel}]`, `rel` = child | related | depends-on (absent = related; one link per target; no self link; schema `entryLinksSchema`). The **project owns its children** (`rel: child` on the project; the Children panel, `?parent=` and `?project=` use them). Skills have no `links`. `ctxman:` links in any body are _mentions_ (shown as Mentions / Mentioned by). Incoming labels: Parent, Required by, Related, Mentioned by. Contexts are not graph edges (the "Linked from contexts" panel stays). Check rules `links/relation-target` (warning) and `links/relation-self` (error).
- **Links in prose**: inside a bundle `/x.md` (bundle root) or `./x.md` must resolve to an existing file; across entries ONLY `ctxman:<dataset>/<slug>` (a `/feature/x` path would be read as a bundle path). Missing `ctxman:` targets are warnings; the preview draws broken links dashed (`a.cx-link--broken`).
- **reference** `uri` (rules in `src/lib/remote-uri.ts`, never a generic URL validator): `remote-repo` = git URI (`git@host:org/repo.git`, `ssh://git@host/org/repo.git`, `https://host/org/repo[.git]`); `remote-skill` = git URI OR `https://…(.tar.gz|.tgz|.zip)` archive, shown with a derived `git`/`archive` badge. Read/written through `src/lib/reference-io.ts` (CRUD API + DataForm; `listReferences()` also reports invalid files); a write is visible on the next request.
- **skill** frontmatter is strict: `name` (== dir), `description`, optional `license`, `compatibility`, `metadata`, `allowed-tools`.
- **context** = pointers, never vendored content; no duplicate links, no link to `context` or `recipe`, `name` immutable. Always read/written through `src/lib/context-io.ts` (atomic write).
- **recipe** = a saved Context Inflate composition (`target` claude-code|codex|generic, `layout` grouped|flat, `contexts`, ad hoc `items`, `markdown` blocks, `overrides`, `order`, per-kind `defaults`, `preamble`, `output` = `{dir, contextFile, primary, allowNonEmpty, stubs}`; overrides and defaults also take `material` + `materialOptions`); strict schema, `name` immutable, NOT linkable (`LINKABLE_DATASETS` excludes it). Always read/written through `src/lib/recipe-io.ts` (atomic write, key order fixed by `serializeRecipe`). Seven check warnings: `collections/recipe-context-missing`, `recipe-item-missing`, `recipe-override-stale`, `recipe-order-stale` (the last two only when every listed context exists and is valid), `recipe-output-dir-relative`, `recipe-material-invalid`, `recipe-primary-invalid`.
- **YAML data files** (reference, context, recipe) start with line 1 `# yaml-language-server: $schema=http://127.0.0.1:4321/api/schemas/<ds>` (the origin comes from `CTXMAN_SERVER_ORIGIN`; VS Code resolves it while ctxman runs). The io writers and `templates.ts` add it through `withSchemaComment(ds, body, origin)`; the serializers never do. The check `collections/yaml-schema-comment` (warning) accepts any loopback origin and port (127.0.0.1, localhost, [::1]) and an optional `.schema.json` suffix for that dataset, and flags anything else or a missing line; `pnpm run fix:yaml-comments` repairs. The in-browser YAML editors never show the line (they match schemas on the fake `file:///data/<ds>/…yaml` model path).
- Freshness = fs mtime (max over the entry dir) computed per request; `stale_after` reached = stale.
- Create entries with the scripts or the `/new/<ds>` forms (never copy folders); finish with `pnpm run check` at 0 errors / 0 warnings.

## Tech (binding; the why is in italics)

- **Runtime**: Node 24 runs `.ts` directly, never transpile (scripts, e2e helpers). _Type stripping: erasable syntax only._ pnpm 11 (`packageManager`). Scripts that need the data dir run `node --env-file-if-exists=.env`.
- **TypeScript**: `typescript@next` 7.1 nightly (native `tsc`). _`@astrojs/ts-content-mapper` (tsconfig `contentMappers`) makes the same `tsc` check `.astro` files, so `astro check` is NOT used and `@astrojs/check` must not be installed._ `noUncheckedIndexedAccess` stays off (Astro's own components fail under it).
- **Framework**: Astro 7.4.0, `output: 'server'`, `@astrojs/node` standalone, `security.allowedDomains` = 127.0.0.1 and localhost (see Origin check). _No content collections: the data layer is plain `node:fs`, so a built server is always current._ Markdown via Satteri (`@astrojs/markdown-satteri`, rendered per request in `src/lib/markdown.ts`); never add `@astrojs/markdown-remark`.
- **UI**: React 19 islands (exactly 10, all `client:only="react"`): SearchWidget and Shortcuts (`Base.astro`, every page; Shortcuts = the `?` help dialog plus the `c` / `l` keys), Forge, Inflate, ToolsRunner, DocEditor (okf + skill detail and sub-doc pages), MarkdownTargets (`/context/<slug>`, `/recipe/<slug>`), DataForm (reference/context/recipe `?edit=1` and `/new/<ds>`), EntryTools (okf/skill/reference detail and doc pages), NewEntryForm (`/new/<ds>` for okf + skill) + react-aria-components kit + vanilla CSS. Everything else is SSR Astro. Forge and Inflate bundle Monaco; the other islands load it lazily (`LazyCodeEditor`) or not at all.
- **Theme**: `cybercore-css` 0.3 (dark only) as base layer; Inter Variable + Hack self-hosted from npm (no CDN, no Google Fonts). Information-dense layout.
- **Editing**: Monaco (`monaco-editor` + `@monaco-editor/react`, loaded locally via Vite workers) for EVERY multi-line markdown/JSON/YAML input; plain `TextField` for single-line values. `monaco-yaml` 5.5.1 gives YAML editors diagnostics, hover and completion from `schemas/*.schema.json` (see Editor).
- **State**: nanostores + `@nanostores/react`; the URL carries all page state.
- **Validation**: `arktype` 2.2.8 is the ONLY validator (a runtime dependency; also in `vite.optimizeDeps.include`): Types in `src/datasets/schemas.ts` give runtime validation, TypeScript types and the JSON Schemas; zod is NOT a dependency of ours and importing it is banned by oxlint `no-restricted-imports` (it only exists as a transitive dependency of the MCP SDK).
- **MCP**: `@modelcontextprotocol/server` 2.3.1 (v2 SDK line, not `@modelcontextprotocol/sdk`); tools are registered with `McpServer.registerTool` whose `inputSchema` is an arktype Type (Standard Schema).
- **Other**: fuse.js 7 search; `yaml`; oxlint + oxfmt (`.oxlintrc.json`, `.oxfmtrc.json`); vitest 5; Playwright 1.64.
- New dependency: `pnpm add`, record it here. Add new client deps to `vite.optimizeDeps.include` in `astro.config.ts` (prevents mid-session dev reloads).

## Coding rules

- **TypeScript only.** Erasable syntax: no `enum`, `namespace` with values, constructor parameter properties, `import x = require`; use `as const` + unions. Relative imports carry the extension (`./x.ts`, `./X.tsx`); `import type` for types; `.ts`/`.tsx` never import `.astro`. Import CSS packages from CSS, not TS (TS 7 side-effect import check).
- **Layering of `src/lib`** (each file's header comment names its kind; THREE kinds, no file under `src/lib` imports `astro:*`): PURE (no fs; browser-safe), NODE (`node:fs` ok), SERVER (`http`, `run-script`, `ide`, `entries`, `mcp/*`: server only). Pages, API routes and `src/middleware.ts` import `astro` types and `astro:middleware` only. PURE: `text`, `object`, `relations`, `shortcuts`, `frontmatter-patch`, `link-insert`, `reference-yaml`, `schema-comment`, `yaml-doc`, `names`, `reorder`, `json-schema` (scripts/tests only), `forms/*` (incl. `entry-form`), `datasets/schemas`, `datasets/validate`. NODE with fs: `data-dir`, `migrate-index`, `entry-index`, `entry-io`, `entry-create`, `atomic-write`, `doc-io`, `reference-io`, `schema-check`; `markdown` (Sätteri, memoized) and `skill-check` are NODE without fs calls. SERVER: `entries.ts` (everything pages, API and MCP read: lists, details, search index, relation graph), `http.ts`, `lib/mcp/*`. In `src/lib/inflate`: `catalog`, `recipe`, `expand`, `material-plan` (also every type that crosses the inflate API) are PURE (the Inflate island may import only these); `markdown`, `render`, `pipeline` are NODE without fs calls of their own; `fs-sources`, `write`, `output-dir`, `material-exec`, `dir-plan` and `recipe-io.ts` are NODE with fs (`dir-plan` also imports `proc`, so scripts never do); `jobs.ts` and `src/lib/proc.ts` are SERVER. Never import fs/SERVER files from an island; no barrel `index.ts` there. Scripts import only `src/datasets/*` and PURE/NODE libs; tests may add SERVER libs; neither imports `astro:*`. `src/ui/editor` touches `self`/Monaco: import it only from `client:only` islands.
- **Validation**: call arktype only through `validate(schema, input)` / `assertValid(schema, input, what)` in `src/datasets/validate.ts`; it returns `{success, data}` or `{success: false, issues: ValidationIssue[]}` (`{path: PropertyKey[], message, code, kind}`, `kind` = `unknown-key` | `custom` (a narrow: duplicates, applicability) | `other`). It prunes `undefined`-valued keys first; custom narrows only run once the document is structurally valid; an unknown key's issue path is the key itself with message `Unrecognized key "x"`. Messages carry arktype's `(was "x")` suffix; `findings.ts#describeIssue` maps the wording (Required, invalid date, unknown key, stripped path prefix, friendly recipe-defaults text). Loose objects keep unknown keys; strict ones use `'+': 'reject'`. Never import zod and never call a Type directly. Tool input Types for MCP must stay JSON-Schema-expressible (no `.narrow`, no `string.date.parse`).
- **Read path (okf + skill)**: the DISK is the truth on every request; there is no content layer and no watcher. Lists, summaries, details' frontmatter, bodies, the relation graph and invalid-file reporting read through `entry-index.ts` (one scan, cached per entry dir by file `(mtimeMs, size)`, 200 ms memo; every write route calls `invalidateEntryIndex()`), so a PATCH, state change or create shows on the very next request and an invalid file is listed with its issues. Bodies are rendered per request by `renderMarkdown` (Sätteri; memo keyed by sha1 of the source, 256 entries) and then `rewriteRenderedHtml`. The search index (`buildSearchIndex` in `entries.ts`) walks the bundles on disk (the entry `index.md` as the entry doc, every other `.md` except nested `index.md` and `log.md`). References are read through `reference-io.ts` (`listReferences` returns `{items, invalid}`), contexts and recipes through their io modules.
- **Origin check**: mutating routes call `checkOrigin` (`src/lib/http.ts`): no `Origin` passes; an Origin equal to `url.origin` passes; else protocol and port must match and either the hostnames are equal or both are loopback (127.0.0.1 / localhost / ::1), or the Origin equals the `Host` header; anything else is 403. `security.allowedDomains` in `astro.config.ts` makes the built node server trust the Host header (otherwise it rebuilds `Request.url` as `localhost` and refuses `Origin: http://127.0.0.1:4321`); `pnpm run test:prod` guards this.

The footer "?" button is `[data-shortcuts-open]`. New shortcut = new row in `SHORTCUTS` + `keyboard-shortcuts.md`.

Cancel is always `secondary`; Retry is `size="sm"` except as an `EmptyState` action; a destructive trigger is `ghost` and its confirm button `danger`; icon-only buttons use `Icon` (`close`, `arrow-up`, `arrow-down`, `external`, `plus`), never glyph characters. Dialogs with a list, an editor or more than three fields use `Modal size="large"` (fixed `min(60rem, 90vw)` x `80vh`, the body or list scrolls inside); confirms and two- or three-field forms stay auto-sized.

All our rules live in `@layer cx-tokens|cx-base|cx-kit|cx-app|cx-prose|cx-utilities`, declared AFTER cybercore's `reset…utilities`. Astro components use HTML twins of kit classes (`ck-*`); never put `cyber-*` classes on `ck-*` elements or form controls. Dataset colors: `--ds-<id>` in `tokens.css`. **Ownership rule**: kit CSS owns colour-by-kind (`ck-status`, `ck-notice`, `ck-error`), label typography (`Label.css`) and the entry line; app and island CSS own placement, size, grid and spacing only and never redefine a `data-kind`/`data-tone` colour. Tokens: `--input-bg`, `--bg-deepest`, `--code-fg`, `--terminal-fg`, `--row-hover-bg`, `--bar-h`, `--toolbar-h`, `--bar-w`; no raw `--cyber-*` outside `tokens.css`. `tests/unit/css-classes.test.ts` fails on a `ck-`/`cx-` class that is defined in CSS but unused, or used but undefined (explicit commented allowlists inside; prefer removing a hook class from the markup).
- **Editor**: Monaco is mounted by `CodeEditor` (kit barrel: Forge, Inflate) or `LazyCodeEditor` (`React.lazy` with a same-size `testId` fallback: every other island); both take the same `CodeEditorProps`. Markdown models get link completion registered ONCE in `monaco-setup.ts` (`link-completion.ts` + pure `link-insert.ts`): `ctxman:` (target), `](` (destination), `[[` (whole link) and Ctrl+Space; not a bare `[`. "Insert link to entry…" is Mod+Alt+K (Monaco binds Mod+Shift+K to delete line) plus a context-menu item, opened through `useInsertLink`, which focuses the editor BEFORE the picker mounts so react-aria restores focus into it. A YAML editor of reference/context/recipe passes `schemaDataset`: the model path becomes `file:///data/<ds>/<testId>-<id>.yaml`, which the schema `fileMatch` needs (`inmemory://` resolves nothing); monaco-yaml markers (owner `yaml`) coexist with the `ctxman` markers, and only `YamlIssue`s with `!coveredBySchema` are passed as `markers`. monaco-yaml needs three shims together (remove none): the `createWebWorker` adapter in `monaco-setup.ts`, the Vite alias for `monaco-editor/esm/vs/editor/editor.worker.js` and the `monaco-yaml > …` entries in `optimizeDeps.include`. Schemas are imported statically. After changing the Type of a yaml dataset run `pnpm run gen:schemas` (`check:schemas` is the gate).
- **Save model of in-browser editing**: explicit Save only (button or Cmd/Ctrl+S; no autosave). IDE edits show on the next browser reload (nothing watches the data dir). A successful write reloads the page itself, in dev and in a built server alike: a doc save and the state select after ~150 ms (`RELOAD_AFTER_SAVE_MS` in `src/stores/doc-editor.ts`, `STATE_RELOAD_MS` in `src/scripts/shell.ts`), the EntryTools dialogs at once (`src/ui/entry/after-write.ts`), `data-form.ts` navigates directly; a doc save returns to preview, dims it (`data-stale`) and remembers "Saved" in sessionStorage (`last-save`). Doc saves send `ifUnmodifiedSince`; a 409 opens the ConflictDialog (Keep editing / Load disk version / Overwrite). Validator findings show after a save, never block it.
- **Drafts**: unsaved text of DocEditor, MarkdownModal, Forge and Inflate is mirrored to **localStorage** (`draft-backup.ts`, key prefix `ctxman:draft:`, 14-day TTL, `{text, base, savedAt}`) and restored after any reload with a "Restored unsaved changes" banner (`DraftNotice`, one component in `src/ui/edit` for DocEditor, MarkdownModal, Forge and Inflate; `data-stale` when the file changed on disk since: saving then overwrites it). These islands have NO native `beforeunload` prompt (a reload after a write cannot be told from a close); in-app discard/confirm dialogs and the Forge/Inflate `popstate` confirm stay. DataForm and NewEntryForm (no persistence) keep `useUnsavedGuard`.
- **Shared editing layer**: `src/ui/edit/` (SaveBar, ConflictDialog, TagEditor, YamlIssues, `api.ts` `getJson`/`sendJson` that never throw, `draft-backup`, `last-save`, `useUnsavedGuard`, `DiscardDialog`, `useDraftField`, `useSaveShortcut` (capture-phase Mod+S, the one island listener; the Forge/Inflate stores keep their own), `DraftNotice`, `saveStatusView`/`failureText`, `edit.css`) is browser-only with NO Monaco; import its files and kit parts by file. `src/lib/names.ts` holds `nameProblem` and the tag rule. `ensureEntries`/`ensureAllEntries`/`loadAllEntries` in `src/stores/entries.ts` feed pickers and completion; `parseEditUrl` in `url-state.ts` reads `edit=1` and `view`. `$docEditing` (doc-editor store: a DocEditor is mounted AND in edit mode, not just `?edit=1`, which the reference form uses too) is what locks EntryTools buttons and the state selects (`Leave the editor first`) and holds back their post-write reload.
- **URL is state**: anything that selects data lives in the URL. List: `q`, repeated `state`/`tag`, `sort` (modified|name|state), `type` (reference), `project` (children of a project). Search: `search=1&sq=<query>&in=<ds,ds>` (never `q`). Forge: `context`, `dataset` (a linkable dataset or `all`), `q`, `state`, `tag`. Inflate: `recipe` (slug or `new`), `view` (compose|preview|run), `dataset` (ad hoc tab, or `all`), `q`, `job` (only with `view=run`), `paths` (`absolute`; relative is the default). Tools: `add`. `/new/<ds>`: `parent`. Detail and doc pages: `edit=1` (set with `replaceState`: never a history entry; removed after a save); yaml datasets add `view` (form|yaml). Use `src/lib/url-state.ts`. Not URL state: unsaved edits, action results, ephemeral UI (open dialogs).
- **nanostores pattern**: URL-synced stores read `location` in `onMount`; actions are plain functions that set stores and call `history.pushState/replaceState`; `popstate` re-reads the URL and never writes history; time comes from `$now`, not `Date.now()` in render; `useState` only for local transient drafts.
- **React**: follow the Rules of React (pure render, no setState in effects, no ref reads in render, no mutation). React Compiler is off, but oxlint `react-hooks-js/*` rules enforce compatibility. A prop named `children` is overwritten by Astro's slot children: pass lists as `childEntries`.
- **API**: JSON only via `src/lib/http.ts` (`json`, `apiError`, `readJson`): `cache-control: no-store`, errors `{error, message, issues?}`; mutating routes answer 415 (not JSON), 403 (Origin check above), 400 (bad body), 404, 409 (exists). `PATCH /api/entry/...` edits only the given top-level keys by range-based text splicing (`frontmatter-patch.ts`, every other byte stays), under a per-file lock (`withFileLock`), and NEVER writes frontmatter that fails the dataset schema (400 `invalid`, nothing written; 409 `conflict` when `ifUnmodifiedSince` differs from the file mtime; 422 `invalid-file` when the file's frontmatter is unusable). `PUT /api/doc/...` is the opposite: it always saves, returns validator `warnings` (incl. `links/*`), 409 `conflict` (body carries the CURRENT `lastModified`), 413 above 512 KB, 422 `not-text`, and never creates a file; `POST /api/doc/...` creates a concept (409 `exists`). `POST /api/ide/open` answers 501 `ide-not-found` / 500 `ide-spawn-failed`. `GET /api/schemas/:dataset[.schema.json]` answers 404 `unknown-dataset` / 500 `schema-missing`. `/api/inflate/render`, `/write`, `/plan`, `/run` are POST-only and need the same checks; `/write` answers 400 `bad-path` / `write-failed`; `/run` answers 400 `no-dir` / `bad-dir` / `dir-not-directory`, 409 `dir-not-empty` / `manifest-invalid` / `busy`; `/jobs/:id` 400 `bad-id` / 404 `not-found`; `/jobs/:id/cancel` 409 `not-running`. `/api/scripts/:name` runs only `src/lib/scripts-allowlist.ts` entries, answers 200 even when the script exits non-zero, 404 for an unknown name. Every route answers 503 `data-dir` while the data dir is unusable (middleware).
- **MCP** (`src/pages/mcp.ts` -> `src/lib/mcp/http.ts`): `POST /mcp`, Streamable HTTP, stateless (one `McpServer` per request, no sessions), served by the same Astro server. `GET`/`DELETE` answer the SDK's 405; a wrong content type is 415 and a 2025-era POST without `Accept: application/json, text/event-stream` 406. The Host header must be loopback and an Origin, when present, loopback (403 otherwise; no Origin passes). Tools: `search`, `list-datasets`, `list-entries`, `get-entry`, `list-bundle-files`, `read-bundle-file`, `get-context`, `render-recipe`, `check-data` (read) and `create-entry`, `patch-entry`, `append-context-links`, `append-log` (write; immediate, last write wins). Resources: `ctxman://{dataset}/{slug}` and `ctxman://{dataset}/{slug}/doc/{+path}`. Tools reuse the same lib modules as the API (never the API over HTTP) and return markdown plus `structuredContent`. Client setup and the full tool table: `concepts/mcp.md`.
- **Cross-platform**: OS-level work uses `node:fs`/`node:path`/`node:util`; spawn `process.execPath` with argv, `shell: false`; no bash/sh scripts. The exceptions: the IDE launcher (`src/lib/ide.ts`) spawns the user's `code` command with `shell: false`, detached (only a win32 `.cmd`/`.bat` goes through `cmd.exe /d /s /c`), and Inflate runs spawn `git`, `tar`, `unzip` through `src/lib/proc.ts` (argv, `shell: false`, never a shell string).
- **Files under the data dir**: every path that comes from a request goes through `safeJoin` / `resolveBundleFile` (`src/lib/bundles.ts`: no `..`, no absolute path, realpath must stay inside the entry dir); writes are atomic (`writeFileAtomic` in `atomic-write.ts`: dot-prefixed temp file in the same dir, then `rename`). The IDE opens only an entry dir (or the data dir for yaml datasets) with a file inside it, never a file alone, and the request never chooses the executable.

## Testing rules

- Unit (`tests/unit`): PURE/NODE/SERVER libs and stores only (no `astro:*`). `tests/unit/setup.ts` (vitest `setupFiles`) pins `CTXMAN_DATA_DIR` to an EMPTY temp dir (and `CTXMAN_SERVER_ORIGIN` to the default) for every test file, so a test that forgets its own dir sees an empty corpus, never the repo. Build fixtures in OS temp dirs (`tests/unit/fixtures/data-fixtures.ts`); for realistic data call `copyCorpus()` (`tests/unit/fixtures/corpus.ts`: copies `tests/data` into a temp dir; `cleanupCorpus()` in `afterEach`). NEVER read or write `tests/data` (or any real data dir) directly (reading the committed `schemas/` is fine); CLIs run with `CTXMAN_DATA_DIR` set. New lib behavior or bugfix = new test.
- Prod smoke (`tests/prod-smoke.ts`, `pnpm run test:prod` after `pnpm run build`): a framework-free check of the BUILT server (origin check, saves, schemas, `/mcp`); keep it green when touching origin checks, middleware, `astro.config.ts` or `/mcp`.
- CSS guard: `tests/unit/css-classes.test.ts` scans `src/**/*.css` against markup/code for unused or undefined `ck-`/`cx-` classes; a new hook-only class goes on its allowlist with a reason, or is dropped from the markup.
- E2E (`tests/e2e`): Playwright against the BUILT app, `fullyParallel`, workers = half the cores, 2..8 (`--workers N`; measured: 360 tests in about 36 s on 7 workers, down from 402 s serial on `astro dev`). `globalSetup` rebuilds `dist/` when it is older than `src`/config (`E2E_BUILD=auto|always|never`) and creates the shared read-only git fixture (`.tmp/e2e/git`). The worker fixture (`tests/e2e/fixtures.ts` + `server.ts`) starts ONE `node dist/server/entry.mjs` per worker on `E2E_BASE_PORT` (4400) + worker index, with its own data copy `.tmp/e2e/w<N>/data` (root `E2E_ROOT`), fake IDE command and record (`.tmp/e2e/w<N>/ide/`), log `.tmp/e2e/w<N>/server.log`, `CTXMAN_SERVER_ORIGIN=http://127.0.0.1:4322` and `CTXMAN_TEST_HOOKS=1`; there is no `prepare-data.ts` and no `astro dev`. Specs import `test`/`expect` from `./fixtures.ts` (lint-enforced) and start no servers; `dataPath()`/`E2E_DATA_DIR` are the current worker's copy. Specs rely on seed entry names and counts (`kb/ctxman`, `context/ctxman-dev`, `recipe/ctxman-dev-brief`, `project/ctxman-v1` with 11 children, 4 seed tasks): do not rename or add to seeds without updating specs; `e2e-*` names are reserved for specs (a spec that adds children uses its own `e2e-*` project); never write a seed entry (copy it, e.g. `createRecipeCopy`). Tests of one file may run in different workers: use `mode: 'serial'` only for a real chain (say why in a comment), and clean up in `afterAll` what `beforeAll` created. Inflate runs use a local git repo via git `insteadOf` (env `GIT_CONFIG_COUNT/KEY_0/VALUE_0`) and run with NO step delay; a test that needs a slow or cancellable run sends header `x-ctxman-step-delay-ms` (`slowInflateSteps(page, ms)`; honoured only under `CTXMAN_TEST_HOOKS=1`, the e2e servers); every run goes into an OS temp dir, NEVER into `~/ctxman-inflate/ctxman-dev-brief`. Nothing watches the data dir, so a write made outside the browser (API, fs) never reloads a page;.
- **E2E waits are events, never time** (oxlint bans `waitForTimeout`, `setTimeout`, `setInterval` and `timers/promises` under `tests/e2e`): request -> `waitForApi`/`afterApi`/`page.waitForResponse` created before the action, then read the file once (the server writes before it answers; no `expect.poll` of a data file); reload -> `afterReload`/`nextPageLoad`; DOM -> web-first assertions (`toBeVisible`, `toHaveText([...])`, `toHaveAttribute`, `:focus`), row order -> `expectOrder`; page state -> `page.waitForFunction`; Node-side state without an event (job status, IDE record) -> `pollUntil` (25 ms) only; "file changed on disk" -> `bumpMtime`; "nothing happens within T" -> `page.clock.install()` + `runFor(T)` or a fake-timer unit test; loading states -> `page.route` + `gate()`. Default timeouts (a first Monaco mount may take `{ timeout: 15_000 }`); no `test.setTimeout` increases.
- Running specs by hand: `pnpm exec playwright test <spec> --output test-results/<name>` (gitignored; default output collides across runs); to run two suites side by side give each its own `E2E_BASE_PORT` and `E2E_ROOT` (and `E2E_BUILD=never` once `dist/` is fresh); debug with `--trace on` (traces are off unless a test is retried). Locate by `data-testid` (`grep -rn data-testid src`; registries in `plans/UI_SPEC.md` §L, `plans/ROUND2_UI_SPEC.md` §L, `plans/INFLATE*_SPEC.md`). e2e locates statuses by test id and `data-kind`, never by old `cx-*__status` classes. Islands render only after mount: wait for their test ids (EntryTools: an enabled SSR button or `entry-status`). After an in-browser save wait for the reloaded page (`afterReload`). New interactive UI gets a test id.

## Caveats

- **No content layer, no watcher**: every read goes to the filesystem, so `pnpm run dev` and a built `pnpm run start` behave the same for data. A built server needs a rebuild only for CODE changes, never for new entries. Edits made in the IDE or by a script appear after a browser reload (nothing pushes them). `astro dev` still reloads for CODE changes (Vite HMR), and the first browser connection after start gets one reload. The e2e suite runs the BUILT server, so none of that dev behaviour reaches a test.
- **After an in-browser write** (doc save, state select, and the EntryTools dialogs: Details, relations, create, Add to context) the page reloads itself in both modes (~150 ms for a doc save and the state select, at once for the EntryTools dialogs); `data-form.ts` navigates directly. There is no settle reload, no sessionStorage reload counter and no 2 s fallback. Tools output survives a reload via `sessionStorage`.
- A saved doc with unparsable frontmatter is allowed on purpose for the doc editor (warnings only): nothing breaks at runtime, the entry shows an "invalid" banner and is listed flagged, and `pnpm run check:okf` names the file. The frontmatter PATCH can never write such a file. An invalid `reference/*.yaml` is listed flagged but its detail page is a 404 until fixed.
- **`CTXMAN_DATA_DIR` is required** (see Data directory and environment). `pnpm run build` and `typecheck` do not need it; `pnpm run start`, `dev`, the add and check scripts do. In tests it is pinned by `tests/unit/setup.ts` and by the e2e/prod-smoke runners.
- **Open in IDE**: the command is `CTXMAN_IDE_COMMAND` (a name looked up in PATH, or a path; set but missing = 501, no fallback), else `code` in PATH, else the usual VS Code install locations (win32: PATHEXT, `code.cmd`). It is run as `<command> <entry dir> <file>` without flags; `{ dir }` (a directory with a readable `.ctxman-inflate.json`) runs `<command> <dir>`. The Windows `.cmd` path is untested on a real Windows host.
- **YAML modelines** resolve only while ctxman runs at `CTXMAN_SERVER_ORIGIN` (default `http://127.0.0.1:4321`); the check accepts any loopback origin/port, so a file written for another port still passes.
- **MCP** is unauthenticated and loopback-only by design (Host/Origin validation); write tools change files immediately with no `ifUnmodifiedSince`. Keep results compact (Claude Code warns above 10k tokens and caps at 25k): lists default to 20, bodies over 50 KB are truncated with a note.
- Stuck or looping dev reloads, "new dependency" errors: stop the server and `rm -rf node_modules/.vite/deps`.
- Freshness is fs mtime, so `git checkout`/clone resets "modified" times.
- **Inflate**: the document is generated on request from the files on disk. Paths in it are absolute and machine specific. Only an `eager` pointer uses a bare `@path`; every other path is backticked so nothing is force-loaded. Brief quality: every okf kind defaults to `inline-main`; an inline okf item also prints its `description` when the body lacks it; empty template headings are dropped (`dropEmptySections`); markdown blocks nest under their group and are titled by their first heading; a link that does not resolve adds an `unresolved-link` warning. `shiftHeadings` handles ATX headings only. `/api/inflate/write` takes an absolute `.md` path outside `node_modules`, `.git` and the data dir (home is NOT required); the UI default is `out/<recipe>.md`. Clones and downloads in the generated commands use `.ctxman/` inside the target project. Output over 512 KB adds a `large-output` warning. Stale overrides and order keys are only warnings until "Prune stale" removes them; removing a context, item or block in the UI prunes automatically.
- **Inflate into a directory** (`output.dir`, or the run-override `dir`; absolute or `~/…`): `POST /api/inflate/plan` (dry run) -> `/run` (202 job, ONE run at a time, 409 `busy`) -> the UI polls `GET /api/inflate/jobs/:id` every 500 ms. Jobs live in memory (last 20, lost on a server restart; `view=run&job=<id>` resumes after a reload). Per item a `material` is placed (okf symlink|copy at `<ds>/<slug>`, skill copy at `<skillsDir>/<name>`, local-repo symlink / remote-repo clone at `repos/<slug>`, remote-skill install, or `none`); `output.primary` is one such repo. Run overrides go through the pure `applyRunOverrides` BEFORE expansion. A run writes `LLM_CONTEXT.md`, stubs (`CLAUDE.md` = `@LLM_CONTEXT.md` for claude-code, `AGENTS.md` for codex/generic, `.gitignore`; only when absent or unedited) and `.ctxman-inflate.json`, the record of what ctxman owns there.
- **Inflate directory safety**: `dir` must be outside the repo and the data dir (and not contain them), not a filesystem root or `$HOME`, no `node_modules`/`.git` segment; a non-empty dir needs a ctxman manifest or `allowNonEmpty`. A re-run deletes or replaces ONLY paths in the previous manifest that are still what ctxman created: clones with local or unpushed changes, edited stubs and retyped paths are kept and reported; symlinks are unlinked, never followed; every step path goes through `safeJoin` plus a realpath check. `git`, `tar` (bsdtar; `unzip` fallback) are system tools: a missing one demotes only the items needing it to `none` with a `tool-missing` warning. Git runs with `GIT_TERMINAL_PROMPT=0` and ssh BatchMode. Directory links are junctions on Windows, which is untested.
